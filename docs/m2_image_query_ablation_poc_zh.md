# 两次提取调用：移除一条错误图片搜索词后，月份回到钟楼

> 2026-09-26；脚本 `scripts/m2_poc_image_query_ablation.py`，完整两臂输入差异、原始提取输出和 token 用量在 `results/analysis/m2_image_query_ablation_poc_20260926.json`。这是对前一阶段图片来源审计的**单会话机制 POC**，没有重灌记忆、答题或判分。

## 预设问题与控制量

源题 `locomo_conv-50_qa65` 的金标为“2023 年 9 月拍摄波士顿钟楼”。历史归档记忆把“上个月”错误地接到 `D27:6` 的图片 `query`（`waterfall white mountains new hampshire`）上，生成“9 月拍白山瀑布”，钟楼记忆则失去这个月份。

两臂均只取 `session_27` 的 `D27:4–8` 五个中文 turn，保留同样的文字、caption、角色、`D27:4` 的 query、Mem0 V3 additive 提取系统提示和当前 `config/locomo_zh.yaml` 中文输出指令。A 用实际适配器输出；B **只把 `D27:6` 的 query 清空**。脚本断言两臂恰好一条消息不同，并记录两个请求 SHA-256。观察日期显式设为 **2023-10-29**，以免日期锚混淆这次机制测试。模型为 `glm-5.3-flash`、temperature 0；每臂一次，SDK 自动重试关闭，总共 **2 次调用**，消耗 **17,598 tokens**（A 8,818；B 8,780）。无 embedding、rerank、图、Jev、答案生成或 judge 调用；不修改现有 Chroma/图。

## 结果

| 提取臂 | 图片记忆 | 日期关系 |
| --- | --- | --- |
| A：原输入 | “戴夫于 2023 年 9 月（上个月）拍摄了一张新罕布什尔州白山瀑布的照片”；另有波士顿天际线钟楼照片 | 钟楼被写成“摄于 2023 年 10 月 29 日左右”，把会话日误当拍摄日 |
| B：仅删 `D27:6` query | “戴夫在 2023 年 9 月（上个月）拍摄了一张城市中钟楼与建筑物的照片”；没有白山瀑布 | “上个月”重新与钟楼相连 |

每臂均输出四条中文记忆。这一结果与归档审计的路径吻合：错误 query 会作为可信图像内容吸收时间关系；删除这一个冲突字段后，模型利用相同对话文字和 caption 保留了目标关系。B 的钟楼记忆没有写“波士顿”，但同一臂的另一条记忆写了波士顿天际线；所以即使进入完整检索/作答，也尚不能保证该题答对。

## 结论、置信度、下一步优化建议

**结论：** 在一个来源已经核清的中文病例中，单独移除错误 `query` 就同时消除了“白山瀑布”错误事实，并把 9 月拍摄关系接回钟楼。错误发生在提取层，不能靠下游图邻域或排序补救。这是单次受控配对的提取结果，尚非总体效果或答题增益。

**置信度：** 输入只差一个字段、输出内容、调用量和日期锚为高；“错误 query 是这个病例关系错接的直接诱因”有较强机制证据，但单次模型生成可能有波动，且 POC 用的是五个 turn、空既有记忆及当前中文提示，不等于 2026-09-25 的完整旧 ingest。总体冲突频率与净得分影响未知。

**下一步优化建议：**

1. 不对全部 888 个 query 一刀切删除。前一审计有对话与 query 一致而 caption 错的反例；先以来源标记保存 text、query、caption，发现矛盾时优先保留原始说话内容及未决状态。
2. 在中文源题中按固定规则再挑少量**query 与文字、caption 一致 / 冲突**的成对病例，只比较提取事实覆盖和虚构细节；先建立是否可复现的错误类型，再投入答案级 POC。所有 live 调用仍应预定数量和停止条件。
3. 对时间事实保存“事件发生时间”和“会话提及时间”的区别及原 turn ID。即便字段冲突解决，也要阻止会话日自动覆盖“上个月拍摄”这类关系。
