# 图片 `query` 被当作事实输入：来源到错误记忆的追踪

> 2026-09-26；复算脚本 `scripts/m2_audit_image_query_provenance.py`，逐条证据见 `results/analysis/m2_image_query_provenance_20260926.json`。只读中文原始数据与八份 2026-09-25 评测归档，零模型调用。

## 输入路径与覆盖量

中文 LoCoMo 有 **5,882 个 turn、272 场会话**。其中 **1,226** 个 turn 带 `blip_caption`，**910** 个带 `img_url`，**888** 个带 `query`；这 888 个也全部带 caption。`src/schema_rsi/benchmarks/locomo.py` 的 `_turn_text` 把二者以 `[shared image: query | blip_caption]` 拼在中文对话正文后。`src/schema_rsi/evaluation/pipeline.py` 在 ingest 时只取拼好的 `content` 构造 messages 并传给 `backend.add_memory`，没有给模型标明 `query` 是搜索词、caption 是图片描述，也没有传 `image_urls`。因此，中文轨道的 888 个 `query` 以英文文本进入提取输入；是否最终成为记忆，仍取决于提取过程。

这个字段并非稳定的图片事实。固定种子 `20260926` 从 888 个 turn 抽取 30 个，仅保守标出至少三处明显冲突：`conv-26 D7:11` 的对话和 query 都在说《Becoming Nicole》，caption 却是船上的狗；`conv-26 D10:16` 的对话和 query 说流星雨，caption 是飞机尾迹；`conv-48 D10:13` 的对话和 query 说艾森豪威尔矩阵，caption 是纸上的剪刀。这三例**不能**用来证明 query 总是错，反而说明不能无条件相信其中任一字段。全量中还能机器复算到 **5** 个 query 写 `sunrise`、caption 写 `sunset` 的直接措辞冲突；其中 `conv-26 D1:14` 后续对话确认是日出，另几处不能仅凭两个字段判真伪。30 个样本的三条人工标注是诊断下界，不是总体冲突率。

## `conv-50_qa65`：查询词进入错误记忆

题目问“戴夫是什么时候拍下波士顿一座钟楼的照片的？”，金标 **2023 年 9 月**，证据定位 `D27:6`。会话日期是 **2023-10-29**。这轮中文文字说“那是波士顿……看看这张，我上个月拍的”；caption 是 *a photography of a clock tower in a city with buildings*，随后 `D27:7–8` 也确认钟楼。但同轮 `query` 是 *waterfall white mountains new hampshire*。整场 `session_27` 的文字和 caption 均没有瀑布；整个 `conv-50` 中“白山/新罕布什尔州”只在这个 `query` 出现。后续 `session_30` 确实另有瀑布照片，但与白山、上个月均无关。

归档中，同一会话产生了两条分离记忆：一条是“波士顿天际线在日落时的照片，照片中有钟楼”，**丢失拍摄月份**；另一条是“上个月（2023 年 9 月）在新罕布什尔州白山拍摄的瀑布照片”，其“白山”只能在原始 `query` 中找到。这条错误记忆在八份归档的该题上下文里均入选；八份复用同一记忆库，因此不是八次独立提取。八次答案都答 **2023 年 10 月 29 日**，把分享照片的会话日期当成了拍摄日期。归档能确认“错误 query → 提取输入 → 带有 query 独有地名的记忆 → 错题上下文”的路径；不能单凭这条链证明移除 query 就一定答对，因为正确的“上个月”关系也已在提取时丢失，答题器还有日期混淆。

这也否定了把该题直接用作“仅改变记忆展示顺序”的 POC：排序不会使钟楼记忆重新拥有“上个月”的关系，模型可能继续按分享日期回答。其他候选时间题也有金标、源 turn 或记忆的歧义，目前没有找到足以隔离排序作用的干净小样本，故没有发起预备的 8 次 live 调用。

## 结论、置信度、下一步优化建议

**结论：** 图片搜索词在中文轨道被当成对话内容送入记忆提取；至少有一条归档记忆携带原始对话和 caption 都没有的 query 独有地名，并与目标问答的月份关系错配。这是发生在图召回、Jev 和提示排序之前的来源失真。查询词与 caption 的冲突方向不固定，不能简单宣布“只保留 caption”或“删去所有 query”会更好。

**置信度：** 代码数据流、字段计数、五处措辞冲突、`conv-50` 来源和八份归档的内容为高；错误记忆由该 query 触发的归因为高但缺少受控重提取实验；这类问题的总体频率及对总分影响未知。

**下一步优化建议：**

1. 在提取输入中保留 `text`、`query`、`caption` 的来源标记。将 query 标为检索提示，避免直接据此断言图像内容；当三者互相矛盾时先保留未决状态及原 turn ID，不生成合并后的肯定事实。
2. 用一个会话做**至多两次**受控提取 POC：同样的中文文字和 caption，A 为当前输入，B 仅移除 `query`；固定模型、参数、会话日期与其余上下文，比较提取出的“白山瀑布”和“钟楼上个月”两种关系。先隔离提取层，再决定是否值得做后续答题层实验。
3. 从带时间关系、且 QA 直接指向图片 turn 的中文题继续找源对话、caption、金标一致的例子。优先修复来源关系丢失，再评估图、Jev 或提示排序收益；归档复用相同记忆，不把重复答案当独立成功或失败证据。
