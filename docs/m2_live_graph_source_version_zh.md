## 问题、范围与方法

此前已核代码可能保留旧节点、历史候选与当前源有版本差异；但这些不证明当前服务实际有旧中文图。本阶段直接问当前配置实例能否提供中文图候选。

只使用 `config/locomo_zh.yaml` 的图配置；先探测TCP，再调用真实HugeGraph只读API。对当前源10个 `zhfull:locomo:*` 用户，每用户分别按user_id枚举Memory（limit=10,000）和Gremlin计数；随后补查全图顶点标签、Memory用户、边标签聚合。Gremlin虽经POST传输，查询全部只读，无drop/addV/addE等写入操作。

当前源来自SQLite只读采集，前后逻辑指纹一致。零模型调用，零建图/清图/源库写入。报告不复制服务地址、配置凭据或原始认证响应。查询之间没有图事务锁，结果限本轮采集时刻。

脚本：`scripts/m2_audit_live_graph_source_version.py`。两份结果分别保留首轮与追加探测：

- `results/analysis/m2_live_graph_global_state_20260928.json`

## 结论、置信度与修正范围

**高置信度，当前配置实例/采集范围：** 当前中文主轨道图尚未就绪。当前服务并非已构建的中文S1/S2/V8图，不能直接用于中文图收益实验。全图只有Memory顶点这一观测描述数据，不能证明schema定义也只有Memory，或推断具体重置过程。

**必须区分此前证据：**

- 旧节点残留是代码与离线回放确认的风险，不是本次服务的实际中文曝光。本次并未找到残留中文Memory，不能宣称有936条旧中文节点需要清理。
- 历史936个候选ID与当前库不符是跨版本迁移边界，不是当前在线候选统计。
- 本次零中文Memory使当前图无法通过当前源版本验收；把这样的graph-enabled运行记成有效Graph臂会混淆“图没有提供数据”和“有图但没收益”。

不推断谁、何时、用哪条命令改变了图；没有服务变更日志。也未检其他图实例、其他机器、磁盘备份或完整schema。旧归档结果及先前机制结论不因此作废。

## 下一步优化建议

1. 当前中文对照实验必须先冻结当前源并构建/核验独立研究图，保存Memory身份、关系构建状态和图manifest。不能用“服务可达”或本地缓存存在代替图数据就绪。
2. 不清空本次所见共享实例：其182条属于其他owner，缺证据说明可删除。候选实验优先离线记录器/独立实例，真实构图前完整核源与提取覆盖。
3. 运行入口应保存graph readiness状态：源ID覆盖、正文指纹、有效图种类/边数、拒绝原因和实际图候选量。未就绪时明确降级为无有效图数据，不把降级结果当作Graph算法的净收益证据。
4. 下一阶段根据当前源和缓存的可验证覆盖，选择能在独立图中完整构建的中文对话/关系病例，优先恢复来源关系与反伤控制；避免现在对这个没有中文图的实例反复测空召回或重做旧候选统计。
