# 中文 Mem0 提取契约：关联旧记忆与说话者字段在哪一层丢失

> 2026-09-29。承接[一次真实隔离写入](m2_isolated_mem0_ingest_zh.md)，只读当前配置/源码，并用两场合成中文消息做零模型、零 embedding HTTP 调用的临时库探针。脚本 `scripts/m2_probe_mem0_contract.py`，结果 `results/analysis/m2_mem0_extraction_contract_20260929.json`。不改生产配置、当前中文库或图。

## 问题和对照

上一段实际写入的 5 条记忆里，3 条混入助手陈述或建议，原始提取回复却把 5 条都标为 `attributed_to: user`。本段检查：当前中文提示如何要求说话者和旧记忆关联；即使提取器正确输出旧 ID，当前写入与项目封装能否保留。

固定使用当前 `config/locomo_zh.yaml`、vendored Mem0 2.1.0 和 `Mem0Backend`。两场合成输入分别是用户说“我喜欢画画”“我也喜欢写作”；第二次的**预置**提取 JSON 显式含第一条真实返回 ID 的 `linked_memory_ids`。向量由进程内固定数组替代，LLM 返回由函数直接给出；因此只验证解析/写入/读出结构，不验证模型会不会产生正确链接，也不验证两句本身是否该合并。

## 直接观测

| 层次 | 观测 | 含义 |
| --- | --- | --- |
| 内置提取提示 | 要求 `memory` 为对象数组，对象含 `text`、`attributed_to`，可含 `linked_memory_ids` | 提取格式允许显式关联已有记忆。 |
| 中文自定义提示 | 要求 `memory` 为“字符串数组”，并含字面 `{messages}` | 与内置对象格式相冲突；本次真实写入的模型仍输出了对象数组，不能说此次因此丢失 5 条。 |
| V3 写入解析 | 对每条提取对象只取 `text`，把 `attributed_to` 复制到向量 payload；没有把 `linked_memory_ids` 复制进去 | 合成第二条明示指向第一条，但原始 Memory payload 无该字段。它不能充当事实级跨场合并链接。 |
| `Mem0Backend.get_all_memories` | 底层第二条 payload 含 `attributed_to=user`；项目包装后 `MemoryRecord.metadata` 不含 `attributed_to`，也不含链接 | 当前项目读出层还丢了原有说话者标签；标签本身也只是模型声明，不是用户原话验证。 |
| 场次日期 | 第二条包装后的 `session_date=2023-02-01` | 这个探针中库存元数据正常；上一段 `add` 返回快照日期为空是返回结构差异，不能混成库存丢日期。 |

两条都成功写入，旧链接确实指向第一条真实 ID，临时库退出即删除。这个对照比单看代码多证明了**当前可执行路径**下字段的实际命运；但并不代表历史运行曾输出该字段。实体索引内部另有同名 `linked_memory_ids`，那是实体到记忆的关联，不能冒充这里的“新记忆指向旧记忆”。

实际隔离写入的提示还有来源角色风险：内置说明明确允许抽取助手建议，并要求区别标注；中文自定义说明也要求从用户和助手消息取事实。真实模型把助手提供的萨曼莎职位、套餐报价和自由交流建议写成用户事实，表明**提示中的角色标签与模型自报标签都不能代替逐子句回源**。本段没有隔离改变提示，不能从一次输出断言是哪一句提示造成污染。

自定义提示还硬编码 `2026-09-26`，而真实请求里的 `Observation Date` 是运行日 `2026-09-29`、源会话日期是 `2023-05-11`。日期锚不同及其单变量小探针已在[相对日写入专项](m2_relative_day_extraction_poc_zh.md)分析，本段只在真实请求中再次看见，不重复把它当新因果结论。

## 结论、置信度、下一步优化建议

**结论：** 当前 Mem0 V3 提示支持输出跨场关联 ID，但实际记忆写入路径不保存该字段；项目封装还未透出底层保存的 `attributed_to`。这两处结构断点会使后续仅靠 `MemoryRecord` 无法区分显式旧记忆链接和模型声称的说话者。与此同时，真实五条的说话者标签全是 `user` 却有三条部分无源，说明单纯透出标签不能当语义准入。

**置信度：** 当前配置与代码、临时库两次写入及原始 payload/包装结果为高；对这一次真实模型输出的三条 partial，沿用上一段逐句人工回源，置信度中高。合成探针不估链接生成率、跨场合并质量、历史发生率或答题收益。

**下一步优化建议：** 先明确字段语义和来源等级：保留提取器声称的 `attributed_to` 与 `linked_memory_ids` 作为**待核候选**，分开记录实际支持 turn/说话者、来源场次、写入场次和纠错状态。若实现透传，应先加离线读写契约测试，再对真实中文跨场样本逐子句验收；无源身份或助手建议仍需拒绝或标待核。清理自定义提示的对象/字符串结构冲突与固定日期应分别做受控单变量验证，不能同时改多个条件后宣称质量提升。整体 Graph/Jev/RSI 净收益仍需独立中文配对答题与反伤检验。
