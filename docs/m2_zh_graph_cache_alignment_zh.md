# 当前中文记忆与图缓存大面积错位：不能直接全量续建

> 2026-09-27。只读脚本 `scripts/m2_audit_zh_graph_cache_alignment.py`；机器结果 `results/analysis/m2_zh_graph_cache_alignment_20260927.json`。不调用模型、不修改向量库或图服务。

## 问题与方法

活图未包含当前中文 ID 后，下一步需要知道本地结构化、主题及嵌入缓存能否支撑隔离重建。脚本从当前 Chroma SQLite 只读取得全部 ID、正文、用户与场次，计算逻辑指纹，再按 ID 与三个 `data/graph_zh/` 缓存逐一求交集。仅用缓存键判断覆盖，不把缓存内容或抽取事实自动视作可靠来源。

当前库有 **1,995** 条，其中目标 `zhfull:locomo:conv-*` 轨道 **1,800** 条；另有 `nf53:locomo:conv-42` 的 **195** 条。先前中文检索实验显式传入 `zhfull` 用户 ID，所以这 195 条不进入那些题的检索；“整个 SQLite 文件只有中文轨道”的说法则不准确。

| 图缓存 | 当前 `zhfull` ID 命中 | 当前 `zhfull` ID 缺失 | 缓存键不在当前整个 SQLite |
| --- | ---: | ---: | ---: |
| 结构化 `structured_cache` | 581/1,800 | 1,219 | 1,124/1,705 |
| 主题 `topic_cache` | 633/1,800 | 1,167 | 1,136/1,769 |
| 嵌入 `memory_embeddings` | 637/1,800 | 1,163 | 1,149/1,786 |

结构化缓存对 `conv-41/42/47/48/49/50` 当前 `zhfull` ID 全部缺失；`conv-26` 几乎完整，`conv-43` 仅缺 12 条，其他分布见机器结果。这是当前版本的**覆盖事实**，不能推断是何次提取、修复或删除导致。缓存按 ID 建键而没有源正文哈希，即使 ID 交集里也不能仅凭命中证明提取内容仍忠于当前正文。

签名篮球的蒂姆和约翰两条当前 ID 都在结构、主题和嵌入缓存中；缓存都含 `signed basketball` 实体，各自正文仍是当前向量库里对应人的签名篮球事实。这保留了该两记忆的**局部建图机制候选**，并不抵消全库缓存的大面积错位，也不证明活图已经连通或总体受益。

## 建图代码的后果

`scripts/build_graph_zh.py` 默认写入现有 `hugegraph`，以用户作用域区分中英记忆；它调用 `GraphBuilder.build_s1(..., reset=False)`，随后增量写主题和聚类。`--force` 仅跳过“已建齐就不运行”的判断，并不会清掉当前库已删除的旧中文 Memory 顶点或旧边。因此，在版本变化后直接 `--force` 续建，可能把过期图记忆留在同一用户的邻域。这是由代码写入语义推得的**风险**，尚未在该服务上观察到旧中文顶点实际残留。当前活图的抽查是英文旧轨道，不能充作该风险已发生的证据。

## 结论、置信度、下一步

**结论：** 现有中文图缓存只覆盖目标轨道约三分之一的当前 ID，且含大量已不在当前库的键。不能把缓存或 `--force` 当作当前纯中文完整图。**置信度：** ID、用户、缓存键交集与代码路径为高；缓存事实质量、错位原因、旧图是否残留为未知。

**下一步优化建议：** 先把构图输入锁定为 `zhfull` 的 1,800 个当前 ID/正文/用户，并记录来源正文哈希；以独立图实例或可清理的独立命名空间建图，避免旧顶点残留。全量 S1/S2/v8 至少有 1,219/1,167/1,163 个未缓存 ID 分别需要结构提取、主题提取、嵌入补齐，调用前必须另定样本与上限。可先挑 `conv-43` 中当前 ID、正文和缓存内容相符的固定小集合，仅做图路径及候选进出验证；不把单例当总体图收益。更广的中文 Jev/RSI 研究应继续按源事实、检索、作答和评价分层进行。
