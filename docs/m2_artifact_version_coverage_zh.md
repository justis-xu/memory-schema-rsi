# 非 JSONL 产物与中文八臂可见记忆版本

> 2026-09-26。接续 `m2_historical_run_coverage_zh.md`，只读结果、实验、图缓存与本地向量库目录的非 JSONL 文件，同时比较八份中文 LoCoMo 主运行中**实际检索到的记忆**。脚本 `scripts/m2_inventory_artifact_versions.py`；逐文件路径、体积、JSON 顶层形状和版本签名在 `results/analysis/m2_artifact_version_inventory_20260926.json`。未调用模型、未修改数据。

## 文件层覆盖

指定目录下有 **196 个非 JSONL 文件**：141 个 JSON、22 个日志、10 个 Markdown 报告、16 个二进制索引、3 个 SQLite、3 个 DB、1 个 pickle。实验目录有 20 份 LongMemEval 前 20 题的单题冻结 JSON，属于小样本快照；不能因为文件体积约百 MB 就看作全量 LongMemEval 评测。`results/analysis` 多为派生审计；`data/graph*` 是结构提取与嵌入缓存；`data/vector_store*` 是当前本地库。清单只核路径、体积和顶层形状，不用文件时间推断历史运行用了哪个版本，也不把派生 JSON 当成独立答题试验。

## 哪些中文跨臂版本关系有直接证据

八份中文主运行各自的 `retrieved_memories` 去重后都是**同一组 1,780 个 ID**，逐 ID 的正文、`session_id`、`session_date`、`user_id` 全部一致；计算出的规范化 SHA-256 签名也相同，且未发现单文件内同 ID 内容漂移。这为八臂按共同题号比较提供了比“文件名相同前缀”更强的可见记忆一致性证据。

五份融合图臂的图候选 ID 集合不同，分别覆盖 1,443–1,634 个不同 ID；这与候选获取和 Jev 扩拉差异相容，但本轮不据此归因。跨图臂同 ID 的正文没有冲突。图候选并集为 **1,674** 个 ID，其中 **1,668** 个也在八臂向量检索并集中，正文逐 ID 一致；其余 **6** 个只见于图候选。因向量检索并集不是完整库，不能把这 6 个直接定性为图中陈旧或错误记忆。

上述一致性只覆盖**曾被检索到**的 1,780 条向量记忆。未召回的库内记忆、图节点／边、向量、重排服务状态以及问答模型的生成条件并无八次不可变快照。现存 `data/vector_store_zh` 和 `data/graph_zh` 是当前文件，不可凭文件时间反推 2026-09-25 每一次运行的状态；既有 `m2_speaker_surface_audit_zh.md` 也注明结构缓存与旧归档 ID 并非完全同版。因此“可见记忆一致”增强配对可信度，**没有证明所有实验条件相同**。

## 结论、置信度、下一步优化建议

**结论：** 不能笼统说中文八臂因记忆文本版本漂移而不可比；八臂实际检索到的 1,780 条记忆完全一致。但完整记忆库和图构建版本没有逐运行冻结，结果小幅差异仍需考虑候选策略、生成／评分波动与未观测状态。大量非 JSONL 产物中，冻结单题快照和当前缓存的证据层级不同，必须随报告注明。

**置信度：** 指定目录文件数、可见 ID／内容／元数据签名和图候选交集为高；未检索到的记忆、历史图状态及 6 条图独见记忆的库内状态未知。文件清单未扫描项目外 HF 原始数据、Git 对象历史与临时缓存；这些不在本阶段“非 JSONL 产物”分母内。

**下一步优化建议：** 把未来每次评测的完整记忆库、图结构、提取缓存和配置都以内容 hash 绑定到运行 manifest；逐题另记图前种子、未截断邻居、重排输入输出与失败记录。历史分析则优先利用这八臂可见记忆一致的优势，在共同题上按源事实和最终入槽查真正的得失；不对未冻结状态构造虚假的严格反事实。
