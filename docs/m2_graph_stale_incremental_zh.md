# 中文增量图的旧节点与旧关系审计

## 问题与范围

前阶段确认 S1 部分提取可进入构图，而中文入口使用 `reset=False`。本阶段继续问：Memory 删除、换 ID 或同 ID 改内容后，旧图结构是否被撤回？检索或 Jev 扩拉是否核对当前 Memory？

范围为当前代码与合成离线回放，零模型调用、零真实图或记忆库写入。使用真实 `GraphBuilder.build_s1`、`GraphRetriever.retrieve/retrieve_fused`、`EvaluationPipeline._evidence_expand`；图存储替换为记录器，扩拉排名替换为确定性桩。没有读取线上图快照，没有测答题效果。

## 方法

合成首版含 anchor、deleted、changed 三条同用户记忆，均连“旧话题”；次版清单保留 anchor，把 changed 内容与抽取关系改成“新话题”，用 replacement 替代 deleted。两次均走增量构图。额外挂一条可达的异用户 Memory，检验现有用户隔离。随后从 anchor 走融合和旁路检索，并以图候选优先的排名桩跑真实 Jev 扩拉路径。

脚本：`scripts/m2_audit_graph_stale_incremental.py`。逐顶点、逐边、候选、当前清单、断言与代码 SHA 见 `results/analysis/m2_graph_stale_incremental_20260928.json`。结果拒绝覆盖；不是历史数据重放。

## 直接观测

|验证点|离线结果|
|---|---|
|次版清单不含 deleted|旧 Memory 顶点及旧边仍在|
|融合与旁路召回|两者均接受同用户 deleted|
|changed 更新内容与关系|新正文仍可经旧话题的残留边召回|
|可达的异用户记录|两条检索路径均拒绝|
|Jev 扩拉后上下文|排名桩选中 deleted，真实转换与扩拉逻辑未阻止|

最后一项只证明候选有进入上下文的通路。排名桩有意把 deleted 排在首位，不代表真实重排会选中，更不代表答案反伤。

## 代码依据

1. `GraphBuilder.build_s1` 增量模式只 upsert 当前输入顶点及当前提取关系，不枚举并移除本用户旧 ID，也不替换同 ID 的完整派生边集合。`build_concepts` 同样追加主题关系。
2. `HugeGraphStore.upsert_vertex` 对已有主键发 PUT/append；`upsert_edge` 查到同类型同端点边即跳过。没有“当前清单之外的 Memory 删除”或“当前关系之外的边删除”步骤。本次记录器用新属性替换同键属性，因此同 ID 场景不测试真实服务 append 的细节；旧边残留由构建器没有撤回操作直接支持。
3. 中文入口的 `--force` 仍使用 `reset=False`，表示重新执行写入，不保证清除旧版本。数量相等与 V8Cluster 存在的跳过条件也不核版本。若换 ID 后重新写入，旧 Memory 数量可能增加，从而继续不满足跳过条件；这是代码推断，非线上现象。
4. `GraphRetriever` 只有 store/settings，无 MemoryBackend；`_same_owner` 校验 user_id。返回的正文取自图顶点，不核当前 ID 或内容指纹。融合池、旁路与 `_evidence_expand` 在 pipeline 再核同用户，随后 `_graph_memory_record` 直接转换图正文，未回查当前库。
5. V8 聚类主键为 owner 加 cl 序号，重算后仍 upsert `V8_IN_CLUSTER`，没有旧边撤回。成员调整可能留下多条簇关系，是静态推断；本轮未运行嵌入或聚类，不能称实测聚类污染。

## 结论、置信度与限制

- **高置信度，代码与离线执行一致：** 当前中文增量构图不是当前 Memory 快照的严格同步；同用户检查不构成版本过滤。删除旧 ID 与更新同 ID 关系是两个不同缺口。
- **高置信度，窄范围控制：** 现有用户隔离在本回放中有效；无需把这一发现混同为跨用户泄露。
- **未知：** 线上当前图中残留多少节点/边、真实候选曝光及答案损害。过去已记录的 Memory DELETE 说明版本变更确实存在，但不能代替同期图日志或因果证据。
- 回放存储按边端点去重查询，采用插入顺序；真实服务的邻接顺序和限额截断可能不同。没有估算全库频率，没有改生产代码或历史结果。

## 下一步优化建议

1. 在检索候选进入重排前核当前同用户 Memory ID，并从当前库恢复正文/日期。不能把“没在本次向量 topK”误当“不在库”：应核完整本用户清单或提供批量精确 ID 查询。
2. 仅做 ID 准入仍无法修复同 ID 的旧关系。增量更新需要替换该 Memory 的派生边集合，或以完整输入指纹生成独立图版本，完成后切换读取版本。共用图实例不能用全图 reset 来清中文单用户数据。
3. 把前阶段每 ID 提取状态、ID/内容/提示模型指纹与本阶段当前源清单及关系版本合成可执行离线准入契约。合法空提取应允许撤回旧边，失败/漏 ID 不能伪装合法空而删除原关系。
4. 下一阶段先验证上述契约的删除、同 ID 改写、合法空、失败保留和跨用户反伤，再决定最小运行路径修复。此契约验收仍须与真实中文答题收益分开。
