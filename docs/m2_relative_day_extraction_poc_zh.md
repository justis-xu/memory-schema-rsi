# 相对日写入链路：日期锚冲突、示例模糊词与三臂小探针

> 2026-09-26。脚本 `scripts/m2_poc_relative_day_extraction.py`，请求哈希、固定源消息、三臂完整提取输出和用量见 `results/analysis/m2_relative_day_extraction_poc_20260926.json`。只调用 `glm-5.3-flash` 提取 3 次，共 25,711 tokens；无 embedding、Mem0 写入、检索、答题或裁判调用。

## 当前写入链路能确定什么

`src/schema_rsi/evaluation/pipeline.py` 的 `ingest_case` 把源会话日期放进一条 `role=system` 的**消息内容**，并放进记忆 metadata；随后 `src/schema_rsi/memory/mem0_backend.py` 调用 `Memory.add(messages, user_id, metadata)`，没有传 `timestamp`。vendored Mem0 2.1.0 的提取路径把这些消息序列化进 `## New Messages`，调用 `generate_additive_extraction_prompt` 时也没有传 `timestamp`，因此 `## Observation Date` 默认是**运行当天**。Mem0 的系统提示却明确要求“只用 Observation Date 解析相对时间”，与嵌在 New Messages 中的历史会话日期形成两个不同的时间锚。metadata 的 `session_date` 只随记忆存储，不自动修正提取提示中的 Observation Date。

同一 vendored 提示还存在精度矛盾：规范要求保留精确日期、把相对时间转换为绝对日期，但示例把 2025-03-15 的 “yesterday” 体检写成 “around March 14, 2025”。这为旧库的“正确日期＋左右”提供了**可疑提示来源**，尚不能证明该示例造成具体历史输出。Mem0 V3 把抽取出的 `text` 直接写入向量库；未见后处理统一加“左右”。

另有独立的说话者信息损失：LoCoMo 适配器保留了 turn 的 `speaker` 字段，但 `ingest_case` 只向 Mem0 传 `role` 与 `content`；本次源片段的乔恩／吉娜因此分别只成了 `user/assistant`。实际提取里出现“用户正在筹备”和“吉娜（对话中的助手方人物）”。它未必解释五道日期模糊题；人物事实和关系边是否因此受损，需要另查旧库中的实际可见范围。

## 三臂最小验证

固定 `conv-30` 的 `D11:13–15`：2023-05-11 的吉娜说“我昨天参加了一个设计实习的面试”。三臂用当前中文配置、相同系统提示、模型、温度和消息片段，`existing memories` 与 `last k messages` 置空。A 的 Observation Date 保持默认 2026-09-26；B 只改为源会话日 2023-05-11；C 在 B 上仅加“明确的昨天／前天／明天／后天不得附加约、左右、前后；保留原词与人物事件”的指令。每臂一次，SDK 自动重试关闭。

| 臂 | 面试记忆 | 旁支现象 |
| --- | --- | --- |
| A：默认 Observation Date | 吉娜 **2023-05-10** 面试，无模糊词 | 工作室计划写“用户”，无日期。 |
| B：源 Observation Date | 吉娜 **2023-05-10** 面试，无模糊词 | 给乔恩“会随时汇报工作室进展”附上“2023-05-11 前后”，原话没有给计划事件日期。 |
| C：源日期＋精度指令 | 吉娜 **2023-05-10（前一天）** 面试，无模糊词 | 保留原相对词，未给工作室计划附加日期。 |

**三臂都正确写出目标日。** 本次没有复现旧库“5 月 10 日左右”，所以不能把日期锚冲突或示例模糊词说成已证实的历史成因，也不能宣称 C 修复了旧题。B 的旁支添日期还说明，单改 Observation Date 不保证所有提取事实更忠实。三个单次输出可能受生成波动影响；本探针只定位值得继续验证的提示与输入问题。

## 结论、置信度、下一步优化建议

**结论：** 当前代码可以静态确认 `Observation Date` 与实际历史会话日没有接通，且系统提示的日期规范和示例相互抵触；本次小探针未证明这些冲突导致旧库的五道模糊日期。目标面试事实在三臂都算对，C 额外保留了“前一天”。源说话者名字在进入 Mem0 前丢失，是另一条需要验证的提取质量线索。

**置信度：** 当前代码路径、请求仅改动的字段、三臂原始输出和 token 用量为高；历史 2026-09-25 全量 ingest 的精确请求没有归档，且当前中文提示在 2026-09-26 改过，因此把当前提示冲突归因为历史五题成因的置信度低；单例提取效果无法外推。

**下一步优化建议：**

1. 先做**消息构造的静态修正 POC**：让每条 turn 的说话者以可解析字段进入 New Messages，并让历史会话日成为唯一 Observation Date；输出完整请求 diff，检查不引入用户／助手和人物混淆。不要直接改旧库或重灌。
2. 再用固定的五道“日期＋无依据模糊词”源片段与一两道已正确日期对照，预注册少量调用，分别检查日期确定性、说话者、事件关系及其他事实反伤。单次三个臂已不足以支持收益判断。
3. 对 `conv-26_qa58` 另测“昨天”是否作为原表达或绝对日期留存；这一题是事实丢失，不能仅靠删掉“左右”处理。
