# RSI 与经验路径实验：历史证据审计

> 2026-09-26。本文只解释已落盘实验能证明什么，作为 `deep_retrospective_zh.md` 的 RSI 专题。当前主场景是中文；归档 RSI/LongMemEval 结果几乎全部为英文，不把它们直接外推到中文。

## 1. 先界定“改进”的证据层级

论文索引里的 [WikiSkill](/Users/xu/git/notebook/笔记/AGI/记忆系统/货拉拉记忆系统/论文/wikiskill/wikiskill.md)将不可变轨迹、可积累知识、可执行技能区分，并用验证门控与回滚保留改善；[ReasoningBank](/Users/xu/git/notebook/笔记/AGI/记忆系统/货拉拉记忆系统/论文/reasoningbank/reasoningbank.md)同时从成功和失败轨迹抽取可复用推理策略；[PAST-Bench](/Users/xu/git/notebook/笔记/AGI/记忆系统/货拉拉记忆系统/论文/past-bench/past-bench.md)要求匹配条件下开启/关闭保留经验，并检查增益是否沿预期的保存、检索、更新路径发生。它们给当前项目一个实用验证梯度：

1. **结构可运行**：图写入、检索路径、回滚都执行了；
2. **证据能到达**：有出处的答案事实进入受限上下文，且不挤出更重要事实；
3. **答案改善**：独立严格判分下，完整答案的净收益超过同配置重复波动；
4. **经验导致改善**：下一批任务只因保留/更新的经验而改善，有可追溯路径，且不依赖当前题金标或未来题信息。

历史 RSI 原型主要走到第 1–2 层，少量有选择的 POC 触及第 3 层；没有第 4 层的中文证据。这里“RSI”指记忆驱动的策略/证据更新闭环，不把单次检索调参称为递归自我改进。

## 3. 经验标签、金标上界和时间顺序的三处关键差距

**经验标签偏宽。** `snapshot_conv26.py` 把原始 `metrics.judge_correct` 写入 `baseline_correct`；这是官方宽松裁判，列表缺一项仍可判对。`analyze_mined_success_paths.py` 只从这些“成功”题挖经验。其 1,409/1,536 的正例比例约 91.7%，远高于全量严格 exact 约 65% 的任务目标（两者不是同一运行，不能逐题相减）。因此“成功轨迹”中可能包含不完整列表或含糊答案；在构建可复用经验前，需要严格完整性标签与 source 支持验证，失败路径也要纳入学习。

**金标上界不是可部署路径。** `analyze_success_evidence_paths.py` 用其他成功题的 `case.evidence` 直接建立支持超边，目标题自己做 leave-one-out。它明确是 oracle 上界。即便 test 对话未参与选择策略参数，构图时仍读入该 test 对话其他题的 gold evidence；“冻结 test +3”只检验阈值在这个 oracle 设置下的转移，不能证明无标签上线可得到相同收益。无 gold 的 weighted support miner 较接近真实系统，但增益只有 9/1,536 个源 turn 全覆盖，且未答题验证。

**金标 ID 自身也需准入检查。** `scripts/audit_gold_evidence_ids.py` 对齐全部中英 QA 后发现，1,536 道 RSI 冻结快照计分题里有 **9 道**的原始 evidence 项匹配不到任何源 turn：复合字符串未拆分、前导零/异常冒号、单独 `D`、以及两条真正不存在的 turn。因快照和离线指标直接用原始字符串拼目标节点，这 9 道不可能被任一检索策略判为全覆盖。结构修复对 623→557 的大方向影响有限，但绝对覆盖率与个案诊断必须注明这一缺陷。更严重的语义错连仍不受 ID 校验约束：如 conv-43_qa56 将钢琴的“四个月”当作小提琴学习时长，conv-43_qa60 将无关 D23:2 当作助攻事件出处。详见 `results/analysis/gold_evidence_quality_zh.md`。

**leave-one-out 不是按时间在线学习。** 离线实验把同一对话的全部 QA 视为可用 peer，再排除当前题；在真实个人记忆系统里，“未来会问到的 QA”并不会预先作为成功经验存在。中文 LoCoMo 也是对话读完后一次性评测所有问题，天然不提供跨任务时间轴。要证明第 4 层，需要按任务到达时间写入已验证经验、固定后续题、在匹配条件下比较保留/不保留，并检查路径使用和回滚。

## 4. LongMemEval 目前只能做小样本参照

翻译版 LongMemEval 清洗数据现有 **470 个中文问题**，但归档主评测是英语：`full_lme_20260923_120251.jsonl` 仅 20 道 `single-session-user`（宽松 19/20），`full_lme_20260924_013242.jsonl` 共 39 道、六题型混合（宽松 34/39）。`lme20_offline_diagnostic.json` 在前 20 题检查答案 session 覆盖，基线 19/20、关键词和图都 20/20；没有答案级图增益，且这个单题型样本接近天花板。不能用它支持跨 session、知识更新、中文或 RSI 的总体结论。

## 5. 对中文后续最划算的验证

1. **先修经验准入而非加图容量。** 用中文逐题漏斗确认 source、记忆、最终上下文和严格答案；只有 source 可核、答案完整、主体与时间正确的执行才进入“成功经验”。其余作为失败教训或待核条目。
2. **优先学习“该补哪类证据”而非“相似问句走哪个 hub”。** 当前中文逐题已见写入漏低频实体、检索漏列表成员、上下文齐却关系错三类；经验条目需包含症状、动作、适用条件、反例和原始 source ID。
3. **先做同对话内因果小试。** 选固定中文小样本，前段任务只产生不看 gold 的经验；后段新题 matched on/off 保留经验，保持相同 15 槽、prompt、模型，逐题记录是否实际取用经验及其依据。只要发现挤出旧证据或答题退化，保留回滚证据；不用为完整 RSI 循环一次性耗完额度。
4. **将三种分数分开。** 源证据覆盖、严格 exact、可追溯的后续增益各自报告；当前 `baseline_correct` 不能替代严格 exact，gold-ID 召回不能替代答案改进，test 参数冻结不能替代无标签在线验证。

本专题仅复算和阅读归档数据，**零新增模型调用**。下一阶段中文 POC 需先写固定题集和调用上限，避免从测试 gold 构图或按最高单轮分数回选设计。
