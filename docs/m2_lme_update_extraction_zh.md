## 问题、固定样本与调用边界

旧来源账只有输入批次和返回记录 ID，无法回答提取器能否保留同场纠正、跨场新旧值及频率限定。使用仓库内已归档的中文 LongMemEval 源片段，选两题：`031748ae` 的早场 5 人说法→本人纠正为 4 人→后场带领 5 人；`f685340e` 的早场每周网球+某个周日计划→后场每隔一周的周日。只选与这些关系相邻的源 turn，逐条保留场次、日期、角色和位置；问题、gold 与人工标签不进入模型请求。此选择是事后诊断样本，不能估全库错误率。

两题各用同一源片段比较基础提取提示与附加来源约束提示，执行顺序为 AB、BA。预先封顶 **4 次 `glm-5.3-flash` 提取**，每次最多 1200 completion tokens、temperature 0、SDK 重试 0、首败即停。实际四次均返回，合计 5,512 prompt tokens、1,480 completion tokens。没有调用答题、判分、检索或图服务，也没有写记忆库/图；即使提取表现改善，也不能宣称答题收益。

## 结论、置信度、下一步优化建议

**结论：** 固定两题上，模型能找出关键数值和多数合法来源轮次，但“事实支持充分”“历史事实保全”“纠正/计划/惯常状态”和严格格式四项没有同时通过。当前输出不能自动写入源图或 RSI 经验，更不能解释中文答题净收益。

**置信度：** 四次精确请求、原始输出、token 用量、22 条来源 ID 合法性和严格 JSON 判断为高；full/partial 与遗漏是对固定原话的人工语义判断，置信度中高。每臂仅一次，输入为源片段而非完整历史，缺稳定性、总体发生率和答题反事实。

**下一步优化建议：** 提取验收必须同时对**输出子句**查来源充分性、对**输入必要事实**查遗漏，并分别核主体、时间窗、纠错、计划/惯常和限定语；仅检查来源 ID 或 JSON 结构不够。对助手衍生身份先置待核而非记为用户事实；网球早场“每周”与后场“每隔一周的周日”要作为不同时间窗同时保留。下一阶段若验证答案，冻结同版中文源、候选与槽数，独立跑少量配对答题和反伤，不把本次提取输出直接计为答案提升。
