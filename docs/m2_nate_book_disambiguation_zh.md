## 来源字段与原子化的局限

当前 owner 可见 metadata 有 `session_id/session_date`、`attributed_to` 等，没有 turn 指针或支持通道。相关龙/太空歌剧记忆的 `attributed_to` 都是 assistant，而非源轮 D9:14/D19:17–19；它可辅助角色归属，不能代替具体人物及事实级来源。ADD history 保存正文与时间，不是完整提取响应或源到事实映射。

代码也支持这一边界：LoCoMo adapter 保留 dia_id 和图片字段，但 `ingest_case` 传入 Mem0 的 messages 只有 role/content，metadata 为会话级。原子提取 prompt 输出字符串数组，缓存亦只有字符串，没有结构化来源指针。英文原子缓存 session9 同样保留系列特征却没有龙；session19 把太空歌剧推荐和偏好拆开。这是不同管线的对照观察，不能证明原子化本身导致或修复中文问题。

因此“一事实一条”仍不足以完成消歧：没有标题的两条原子句可能各自正确，却无法可靠说明它们属于哪次提及、信息来自哪种通道、偏好强度限定在哪个对象上。

## 结论、置信度与优化建议

直接观察的高置信结论：当前中文库已有龙的封面细节；旧两臂选了另一次有明确最爱支持的推荐；两种对象描述都借用了 query；当前与旧该题候选版本不重合；来源字段仅到场次。中等置信的人工判断：题面对匿名对象消歧不足，指定 gold 的“主题是龙”不能只靠封面 query 严格推出。未证明 gold 在实际图片层面错误，也未证明当前答题是否仍错。

1. 用 **源提及锚点** 暂存匿名对象，例如 D9:14 与 D19:17–19，明确这是两次提及的索引，不是两本不同书的实体断言。仅在源明确同名或承接时合并对象。
