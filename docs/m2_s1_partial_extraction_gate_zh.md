# S1构图入口：部分提取失败与完整性门槛（2026-09-28）

## 问题、范围与方法

上一阶段发现当前conv42的Memory ID全部未命中旧结构缓存。本轮核真实入口是否会在缺项/提取失败时继续构图，以及中文增量入口和S1评测重建入口的区别。范围是当前 `StructuredExtractor`、`GraphBuilder.build_s1`、`scripts/build_graph_zh.py`、`scripts/eval_s1_ab.py`；另读RSI lab编译调用确认机制范围。

使用3条合成Memory，4种缓存/响应情况；调用真实extractor/build_s1，但客户端只返回固定JSON或抛本地异常，缓存写入临时目录，图写入内存Recorder。旧图用哨兵Memory表示，用reset调用次数及哨兵是否保留观察副作用。零外部模型/embedding/Graph服务/答案/裁判调用，未改生产代码或真实图。反伤检查包括全失败是否保住旧图、合法空结构是否与失败区别、部分失败是否能绕过门槛、不同入口reset行为。

脚本 `scripts/m2_audit_s1_partial_extraction_gate.py`；机器结果 `results/analysis/m2_s1_partial_extraction_gate_20260928.json`，记录原缓存、真实extract返回、保存缓存、模拟节点边、reset次数和代码SHA。合成故障不代表历史真实发生次数或失分率。

## 入口行为与完整性缺口

### 结构提取

`StructuredExtractor`按ID是否在cache决定pending；混合缓存中的单条空结构仍被当作已有记录，不重新请求。若缓存整体空才在加载时清掉。批请求失败时记录警告并继续，漏返回某ID也不抛整体异常；最后为所有输入ID返回结构，缺项填四类空列表。

因此 `len(extraction)==len(memories)` 不能证明每条处理成功。本地两种部分失败都返回3个ID，但只有1条非空。缓存空可能是合法无结构，也可能是旧失败结果，当前条目没有成功状态、输入正文/提示/模型指纹，不能直接区分。粗暴要求每条都非空会误伤确实没有目标结构的Memory；需要处理状态和合法空结果契约。

### S1建图

`build_s1`先检查user_id、整批全空，然后在reset=True时清图。部分输入缺结构只按空扩展处理，仍创建所有Memory顶点。模拟证明一条非空足以让部分失败整批通过并清图，不能把顶点数量完整当派生信息完整。

这不是针对当前195条自动故障的真实重建，真实服务是否有缓存/响应仍未知；只是当前代码允许的边界。reset=False的模拟保留旧哨兵，也不能把它称为清空旧图。

### 中文入口与评测入口

`build_graph_zh.py`使用 `reset=False`，并继续主题/聚类构建；它不整体清图，也没有在S1部分失败后返回失败状态的完整性检查。旧Memory或派生边是否被清理要独立核，不能仅凭增量写入宣称被新版本替换。

其跳过条件是 `not force and before.Memory == len(memories) and V8Cluster > 0`。本地按原表达式给旧ID集合old-A/B/C、新集合new-A/B/C、相同数量3和一个聚类节点，结果会跳过。这个谓词只比数量，不验证ID、正文、提取或schema版本；没有执行真实入口，因此不证明真实历史有错跳过。

`eval_s1_ab.py`则调用 `build_s1(..., reset=True)`。它只有提取总数打印，没有每ID处理状态验收；相同的部分成功条件可以走清图重建路径。本轮没有调用该评测入口或清真实图。

### RSI范围

当前 `experiments/schema_rsi/schema_rsi_lab/evolve.py` 的编译调用走自有 `compile_graph(data, schema)`，输入固定稀疏候选边；本次S1缓存/清图门槛不是它的promotion gate。不能把S1入口发现直接推广成RSI接受门控已被证明失败，也不重复已审RSI代理评测结论。

## 结论、置信度、下一步优化建议

高置信：真实代码及离线故障注入验证的返回ID、缓存状态和reset副作用。历史故障频率、真实图状态、派生缺失对中文答案的影响未知。本阶段没有生产修复或收益评测。

1. 提取返回每ID的状态：成功有结构、成功合法空、失败/未返回，并附Memory正文、提取模型/提示版本指纹。完整性按已处理状态验收，不能按非空比例或返回字典长度冒充。
2. 重建入口在任何真实写入/reset前完成本批覆盖检查；部分失败保留旧图且记录未完成构建。增量入口也需区分完成/部分完成，并按版本处理旧ID和边，不能只打印完成。
3. 跳过构建改用Memory ID/正文逻辑指纹、schema版本和派生状态；数量与聚类节点只能作粗检查。未来采用独立构建版本验收后切换，防止半成品被评测或接受门控消费。
4. 下一阶段可先离线定义每ID处理状态及构建准入契约，再检查增量模式旧节点清理和检索版本过滤；服务恢复后才做小型同版中文构建/答案对照。持续研究未完成，当前429不妨碍离线推进。
