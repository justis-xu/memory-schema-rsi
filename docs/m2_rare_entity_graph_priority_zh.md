# 中文图候选：稀有实体桥能稳定入池，也会推广旁支

> 2026-09-27。隔离进程内图重放 `scripts/m2_probe_rare_entity_graph_priority.py`；逐顺序、逐题候选进出账 `results/analysis/m2_rare_entity_graph_priority_20260927.json`。不写 HugeGraph/Chroma，零向量、重排、答题或裁判调用。

## 问题、固定输入与规则

此前 `conv-43_qa25` 已确认：蒂姆和约翰两条签名篮球记忆通过同一个仅有两条 Memory 的 `signed basketball` 实体相连；但现行 GraphRetriever 按 support 个数排序、前 30 截断，在不同建图边序下会漏约翰。这里不调最终答案，先只检验**候选截断层**：给“连接种子、且完整 Memory 度数不超过 3 的 Entity 节点”一个优先级，能否稳定保住具体关系桥？它又会带来什么无关候选？

固定当前 `conv-43` 的 211 条中文用户记忆、结构缓存、主题缓存和三道已冻结问句的前 5 向量重排种子；同一 GraphBuilder S1+Concept、GraphRetriever，每节点 15、图候选 30。三题分别为：`qa25` 蒂姆和约翰相似运动收藏品（已知缺约翰签名篮球）；`qa2` 约翰收藏什么（当前无图答案本来可答）；`qa32` 蒂姆去环球影城可能在哪些州（所需州名属于外部推断）。规则不读题目金标：先生成与生产相同的**未截断**候选，再把含稀有 Entity 桥的候选稳定移到前面，其他候选维持生产顺序和 support 结果。比较 ID 升序、降序、固定随机种子 0–49 的 52 种建图顺序。顺序扰动是机制压力测试，不是 52 道独立题。

## 候选层结果

| 固定题；52 种边序 | 现行排序 | 稀有实体优先 | 前 30 候选集合变化 |
| --- | ---: | ---: | ---: |
| `qa25`：约翰签名篮球 ID 进入前 30 | 30/52 | **52/52** | 22 种边序，每次换入 1 条并挤出 1 条 |
| `qa2`：无签名篮球目标要求 | — | — | 23 种边序，每次换入 1 条并挤出 1 条 |
| `qa32`：州名推断题 | — | — | 34 种边序，合计换入 39 条并等量挤出 |

在 `qa25`，现行未截断的约翰记忆位置随边序在第 1–78；稀有优先后它在 52 次中都是第 1。ID 降序时现行排第 69，进不了前 30；规则换入该条，换出一条蒂姆的哈利·波特大会记忆。当前库逻辑指纹为 `61e015ce…`，SQLite 字节哈希前后一致。

但同一规则不懂题目关系。`qa2` 的 ID 升序样本把“蒂姆推荐约翰读《风之名》”作为稀有实体候选换入，问题却问约翰**收藏品**；它挤出另一条蒂姆游览哈利·波特景点的旁支。`qa32` 的顺序扰动会把 MinaLima、《哈利·波特》等候选提前；它们与蒂姆兴趣有关，却没有给出环球影城的州名。候选换入不等于错误答案，但这些负对照说明“节点稀有”不是独立的事实准入条件，广泛套用可能增加最终 15 槽的竞争与噪声。

## 结论、置信度与下一步

**结论：** 对当前纯中文 `conv-43_qa25` 这个具体图桥，候选 cap 前的稀有实体优先修复了边序敏感的漏召回；它同时在不需要该桥的题中改动约半数到三分之二的图候选集合。它是**候选层机制收益与旁支风险**，尚非 Graph 答题净收益。不能从 52 个顺序扰动推全库成功率，也不能据此把稀有优先直接改成全局生产排序。

**置信度：** 当前库 ID/正文、缓存构图、三题种子、候选 ID 和替换账均可确定性复算；对候选与问题关系的病例判断为人工中高。HugeGraph 真实边枚举、缺缓存记忆的影响、统一重排后入槽、答案及挤出反伤仍未知。该缓存只有 `conv-43` 接近齐全，三题不能代表其他会话。

**下一步优化建议：** 在更多缓存版本对齐、源事实可信的中文多人题上，先以**问题关系和种子实体**限制稀有桥准入，而非全局优先；保留原始 30 候选的受保护直证并逐题记录换入/挤出。候选层若能在正例补事实、负例少扰动，再比较统一重排后的真实 15 槽和 ABBA 答案。还须用隔离 HugeGraph 核边序和每节点截断，避免把进程内压力测试当线上图效果。
