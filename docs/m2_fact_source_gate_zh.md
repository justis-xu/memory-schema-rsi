# 事实来源门离线 POC：逐子句判定在固定 23 条上未过停止门

> 2026-10-01。执行 2026-09-29 [综合复盘](m2_integrated_retrospective_20260929_zh.md)"下一段的最小判别实验"。判定输入只有源话轮、候选正文与运行时 metadata；人工 oracle 只做离线验收，物理分离于判定输入。固定开发集、两次运行账与验收账：`results/analysis/m2_fact_gate_devset_20261001.json`、`m2_fact_gate_run_20261001.json`（v1）、`m2_fact_gate_run_v2_20261001.json`（v2）、`m2_fact_gate_verdict_v1_20261001.json`、`m2_fact_gate_verdict_v2_20261001.json`。脚本：`scripts/m2_build_fact_gate_devset.py`、`m2_poc_fact_source_gate.py`、`m2_evaluate_fact_gate.py`。

## 问题、范围与停止门

问题：一个不接收 gold 的事实来源门，能否在固定中文样本上同时保住应保事实并拦住应拦内容。这是[跨仓门槛回放](https://github.com/justis-xu/memory-prompt/blob/master/docs/m2_fact_acceptance_gate_replay_zh.md)建议的下一步评估，此前该报告已证明合法指针＋严格 JSON 拦不住语义错误。本 POC 只做离线验收，零写入：不碰真实库/图、不做答题/裁判/embedding。

停止门（预先固定）：门若把 partial 记忆整条放行（fail-1），或把真人 `assistant` 标签记忆整类拒绝（fail-2），则不接入真实库与图，归档失败原因。

| A | 5 | LongMemEval 工程师早场真实隔离写入返回记忆＋12 个源话轮 | `m2_isolated_mem0_ingest_review_20260929.json` |
| B | 8 | 跨场归并 4 病例（蒂姆写作、城堡、梅拉妮陶艺、公路旅行）×旧/新两候选，源为整场话轮 | `m2_carryover_cache_eligibility_20260928.json` 订正 39 项表 |
| C | 10 | LoCoMo `assistant` 标签记忆（全部第二真人），源为完整场次话轮（含图片 query/caption） | `m2_role_label_source_sample_20260929.json` |

构建断言全过：oracle 字段与门输入物理分离（递归检查）；B 组 oracle 引用的 `dia_id` 全部落入所供话轮；C 组见证正文与中文 LoCoMo 数据集逐字一致（`memory-prompt/eval-datasets/locomo-zh/locomo10_zh.json`）。

## 方法

门 = LLM 逐子句判定（glm-5.3-flash，temperature 0，max_retries=0，45s 超时）＋确定性守卫（absent 强制撤回、partial 禁止 keep、动作与子句一致性、无效引用标注）。每候选 1 次判定调用，JSON 解析失败允许 1 次修复调用。

- **v1**（23 次调用，零修复）：通用来源审计规则。
- **v2**（23 次调用，零修复）：冻结的唯一一次修订，只加严 v1 四个失败根因——助手复述/总结不算用户确认、缺失限定词强制 weaken、未指名身份强制 withdraw、动作一致性入 prompt。预先冻结：同一 devset、累计 60 次封顶（实际累计 46 次）、成败即停不做第三次。

验收脚本另实现 v2 守卫（引用后缀归一＋动作一致性），只修整流不改语义判定；v1/v2 原始输出保留可复查。

## 结果

8 个验收案（4 保 4 拦），v1 通过 4/8，v2 通过 5/8，**两次停止门均 FAIL（fail-1 触发）**：

| 验收案 | v1 | v2 | 说明 |

**停止门判定：FAIL，不接入真实库与图。**

### 失败解剖

1. **A1"含本人"（2/2 次失败，深层）**：用户 turn:10 原话"我在新职位上带领一个4人的工程师团队……一共5人参加团建"并未说明 4 名工程师是否含本人；该消歧只存在于助手 turn:11 的总结。模型两版都把它读作 turn:10 可推出，判 full/keep。这与人工 oracle 的口径（拆不开就不定，"含本人"须撤回）相容但不同——模型把"隐含可推断"当作"有源支持"。加严后的规则 4 也未改变该判定，说明这不是规则遗漏而是模型与人工口径在此类边界上的稳定分歧。
2. **A0 日期锚政策冲突（设计层）**：oracle 接受以场次日期锚支持时间表述（"2023年5月取自本场日期"）；prompt 规定源话轮为唯一依据导致 v2 拒绝日期锚。先在验收口径里定死日期锚政策再进 prompt，是下次必须补的前置。
3. **守卫的真实价值**：v1 raw 的 A0 自相矛盾（全 keep 却 withdraw）与 B_later 引用带 `session_11:` 前缀的"假幻觉引用"都被确定性守卫修复；absent→withdraw、partial 禁 keep 守卫在两版均生效。

### 正向机制（两版稳定）

- C 组 10 条 0 撤回：无整类拒绝，图片 query 渠道线索被正确标注为"非当事人文字自述"（C1 名言、C7 照片）。
- A3 萨曼莎职位/套餐细节/联系方式、A4 自由交流/破冰例子：全部削弱并注明仅助手来源（v1 已达成，v2 保持）。
- 说话者错配有真实捕获：B_older 公路"inner peace"标为玛丽亚的话轮而非约翰自述；陶艺 D17:8 与 D17:10 的说话者区分正确。
- v2 规则 8/9 生效：缺失限定词、未指名同行者两类失败由加严规则直接修复。

## 限制

- 固定 23 条、单模型（glm-5.3-flash）、单一 prompt 家族两轮；不估总体错误率，不外推其他模型。
- oracle 为既有人工判断（中高置信）；验收机械检查按关键词定位子句，子句粒度由 LLM 决定，颗粒度差异会影响计数。
- A0 的 v2 失败含本 POC 设计选择（prompt 与 oracle 的日期锚政策不一致），非纯模型失败。
- 未触碰记忆写入、检索、图与答案；"门通过/不通过"均不构成答题收益证据。

## 结论与置信度

**结论：当前形态的事实来源门（flash 模型逐子句判定＋确定性守卫，两轮规则加严）未过停止门，不得接入真实库/图。** 直接原因是 A1 类"助理总结消歧被当作源支持"的稳定分歧（fail-1），以及 prompt 与 oracle 在日期锚上的口径冲突。同时证明：守卫层能可靠兜住结构性错误（自相矛盾、无效引用、partial 整条放行的降级），但语义层"隐含推断 vs 有源支持"的边界判断未对齐人工口径。负结果是可交付结论：无 gold 的自动逐子句来源门在当前配置下不能替代人工验收。

**置信度**：两次运行的调用数、原始输出、守卫日志、验收计数可复算，为高；oracle 子句标签沿用三份既有人工审阅，中高；"深层分歧"的判断基于 2 次独立失败，中高；对其他模型/提示的推广不下结论。

## 下一步优化建议

1. **确定性预拆分先于语义判定**：括号限定词（如"（含本人）"）强制拆为独立子句再判，不依赖 LLM 自觉；可离线重放 v1/v2 raw 输出验证，无需新调用（未实施）。
2. **逐字引用契约**：要求每个子句给出源话轮中的逐字原话引用，做确定性子串校验；A1 的"含本人"在 turn:10 无逐字对应，可被机械拦截。这是把"指针合法"升级为"引文可验"的最小改动。
3. **日期锚政策前置**：先在验收口径中明确"场次日期锚可作为时间支持"，再写入 prompt 与守卫，消除 A0 类政策性分歧。
4. 若 1–3 仍不能过停止门，按[完成度账](https://github.com/justis-xu/memory-prompt/blob/master/docs/m2_retrospective_completion_zh.md)建议，把来源门定位为入库候选的**拒绝/待核状态**（保守拦截不自动写入），而不是追求全自动放行；人工侧车只做抽验。
