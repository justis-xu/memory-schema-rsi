# 中文答题日期链路：原始字符串错序与图候选日期丢失

> 2026-09-27。历史日期排序审计：`scripts/m2_audit_prompt_date_order.py`、`results/analysis/m2_prompt_date_order_20260927.json`；当前图日期透传探针：`scripts/m2_probe_graph_date_handoff.py`、`results/analysis/m2_graph_date_handoff_20260927.json`。本轮无模型、向量、重排或 HugeGraph 服务调用。

## 问题与数据范围

已有中文图候选入槽日期丢失的证据，但检查接收端时发现另一个上游问题：LoCoMo 官方答题模板声称按时间从早到晚展示记忆，`format_memories_official` 却直接按 `session_date` 原始字符串排序。LoCoMo 日期形如 `7:54 pm on 17 August, 2023`，以时钟开头；字典序不是日期顺序。本阶段分别核：历史实际上下文有多少错序、修正排序后日期能否从当前图源 Memory 传到答题展示。

选定归档是中文无图 `zhfull_locomo_20260925_164645.jsonl`（1,979 题）、英文无图 `full_locomo_finalC_ctrl_20260925_090746.jsonl`（1,986 题），外加英文 LongMemEval-S 39 题和此前冻结的中文 20 题检索样本。两份无图运行的每题 `answer_context_ids` 都能用同条记录的 `retrieved_memories` 按顺序重建；所有纳入统计的记忆日期均能解析。只检查上下文日期顺序，不复算答案或判分。

## 直接观测

中文无图归档的 321 道 temporal 题全部错序；其他四类也全部错序。例：原始字符串排序把 `10:52 am on 27 July` 放在 `7:11 pm on 24 May` 之前。LongMemEval-S 原日期形如 `2023/05/30 ...`，年份在前，本次 39 题的 newest-first 顺序与解析后相同；它只是小归档，不能覆盖所有 LongMemEval 数据变体。

图日期是另一处独立断点：S1 Memory 顶点已有 `session_id/session_date`，但 `GraphRetriever` 输出图候选及 `EvaluationPipeline` 转成答题记录时未携带。已知历史中文融合图臂有 2,042 次图入槽缺日期，2,034 次能从同 ID 向量记录恢复；本轮不重算该统计。用当前 `conv-43` 的两条签名篮球记忆做隔离重放，约翰源记录的 `session_7`、`7:54 pm on 17 August, 2023` 现在可逐层传到图候选、答题记录和官方模板，展示为 `(Thursday, August 17, 2023)`。当前 SQLite 文件哈希前后相同。

## 修改与验证

- `format_memories_official` 先把日期解析成可排序时间，再按 oldest-first 排列；无法解析或缺失日期的记录保留输入相对顺序，放在有日期记录之后。记忆内容和显示用日期转换保持原流程。
- `GraphRetriever` 的 fused、S0、S1 和基础路径传递 Memory 顶点已有的 `session_id/session_date`；融合、旁路以及 Jev 扩拉转答题记录时统一保留它们。缺源日期的图记忆仍显示未知，不从正文猜日期。
- 全套本地测试 29 项通过。新增测试覆盖 LoCoMo 原始日期错序、LongMemEval 现有顺序、图候选日期、融合 Jev 扩拉和旁路答题记录。当前两记忆的隔离探针验证了真实库元数据到最终格式文本的链路。

## 结论、置信度与下一步

**结论：** 过去 LoCoMo 答题器确实在全部检查到的上下文里错误宣称“按时间序”；这是中文和英文共有的展示层缺陷。图路径另有日期元数据丢失，现已在代码中透传。两项修正只改变未来运行；**旧结果不能据此重算新分数，也不能把旧时间题失分归因于错序**。如果历史对照两臂都使用同一错误排序，配对差仍可能有价值，但图臂缺日期会引入额外不对称，须单独验证。

对归档上下文重建、日期比较及当前两记忆透传的置信度高；对真实 HugeGraph 图状态和答题收益未知。下一步在预先选好的中文时间题上冻结相同记忆集合，先单变量比较“只修排序”，再单变量比较“只恢复图日期”，记录答案要素、反伤和同输入重采样波动。不要混着改提示或检索，更不能以本次零模型审计声称准确率提升。
