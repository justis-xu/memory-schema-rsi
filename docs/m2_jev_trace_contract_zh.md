# Jev 首判与扩拉的可追溯记录：补齐同次运行证据链

> 2026-09-27。本阶段只读旧中文归档并修改未来运行的记录字段；零模型调用。历史字段清单由 `scripts/m2_audit_jev_trace_gap.py` 生成于 `results/analysis/m2_jev_trace_gap_20260927.json`，运行逻辑在 `src/schema_rsi/evaluation/pipeline.py` 和 `src/schema_rsi/llm/laya.py`。

## 问题与历史证据

已有 Jev 审计发现：首判实际看到每条记忆前 60 字拼成的摘要，答题器却读全文和可用日期。历史 JSONL 仅有扩拉后的完整候选及最终上下文，缺首判的有序 15 条、候选池及实际请求体。因此不能在同一次运行中回答“低分触发后，新事实是否进入了 15 槽、挤掉了谁”。这次只复核归档字段：decider 1,980/1,980 道有首判分、1,091 道扩拉；laya 1,977/1,979 道有首判分、246 道扩拉。两份归档的首判上下文、首判实际请求体、二判上下文字段均为零。扩拉题中，原 `graph_context_ids` 与最终图候选及最终答题 ID 交集不一致的分别是 530/1,091 和 132/246。这个数字是旧归档的记录缺陷，不是图入槽率或答题效果。

## 新记录契约

Jev 条件成立时，`metadata.jev_stop` 增加 `trace_version=1`。首判保存有序上下文的 ID、全文、正文哈希、会话日期、场次、图路径，以及首轮图候选 ID/路径/支持数/正文哈希；另存首判服务**实际收到的 state body**、摘要哈希与未四舍五入概率。扩拉后对二判保存同样的有序上下文、图池、实际 state 和原始概率。旧 `first`、`second` 两位小数字段保留，方便读旧脚本。若决策服务出错，记录错误类型；不改变原有降级作答行为。

同时按**最终**图候选池和最终 15 槽重新计算 `graph_context_ids` 与 `fused_graph_in_context`，避免扩拉后仍引用首判旧 ID。`LayaClient.evidence_state` 统一构造评估代码和审计日志使用的请求体，保留原先“摘要前 950 字、state 最多 1,000 字”的输入行为。此次没有更改 60 字裁剪、0.4 阈值、扩拉宽度、候选重排或答案提示。

用假向量池、两轮不同图候选和固定概率的离线测试验证：首判 `[v1,g1]`、二判 `[v1,g2]`，两轮实际 state 与请求构造一致，原始概率与旧舍入值都保存，最终图 ID 为 `g2`。运行 `tests/test_jev_trace.py` 与现有融合检索测试共 5 项通过；这只证明记录契约和旧逻辑兼容，不是 Jev 效果验证。

## 结论、限制与下一步

**结论：** 旧归档缺少构造真实首判反事实所需的字段，且扩拉后的图 ID 元数据有可复现的不一致；新记录契约补上了未来同次运行的首判、二判可见证据与最终图来源。**置信度：** 对旧字段缺失、当前代码路径和离线测试为高；对新日志在远端决策服务、真实图与当前中文库上的运行正确性尚未验证。旧归档无法被新字段事后修复。

**下一步优化建议：** 在当前纯中文库选一小批先定题目，运行一次记录增强的 Jev 对照；先只看首判前后是否增加了有源必要事实、是否挤出旧直证、二判是否看到新事实，再决定是否值得对同批题花答题与裁判调用。还需在记录中增加每条记忆的原始 turn 来源；目前会话日期和图路径只是来源线索，不能替代源 turn 证明。评分服务地址或权重版本仍需用脱敏标识归档，避免未来跨版本误比。
