# 事实来源门 v3：确定性守卫使部署形态通过停止门

> 2026-10-01。阶段 1a/1c。零新增模型调用：在 10/1 [门 POC](m2_fact_source_gate_zh.md) 的 v1/v2 raw 输出上离线重放守卫 v3（`scripts/m2_replay_gate_guards_v3.py`、`results/analysis/m2_gate_guards_v3_replay_20261001.json`）。1b（有界模型修订）按预冻结条件**跳过**：纯守卫已达部署停止门。

v2+守卫 v3 的唯一失败案是 `no_whole_partial_pass`——该案按定义度量 **raw 模型行为**（A1 raw 仍整条 keep），部署形态（模型+守卫）已由停止门的部署形态判定单独覆盖为 PASS。**来源门 v3 = v2 判定 + v3 守卫，在固定 23 条上达到"离线达标"。**

## 三个防线的实际效果

1. **括号限定词逐字校验（核心修复）**：A1"4名工程师（含用户本人）"中"含用户本人"在引用的 turn:10 无逐字对应 → 限定撤回、子句降级、动作对齐为 split。v1/v2 两版的 fail-1 均被确定性拦下。附带效果：A4 破冰例子、C8《教父》英文名等括号限定同样被标待核。
2. **日期锚政策**：`截至2023年5月` 与批次锚 2023/05/11 年月一致 → absent 恢复为锚支持（对齐 oracle 口径"2023年5月取自本场日期"），修掉 v2 的 A0 保守误杀。修复过程中纠了两个守卫 bug：月份字符串未归一（"5"≠"05"）、无年份子句误触发锚恢复。
3. **引文覆盖率度量（回答 1b 必要性）**：v1/v2 共 162 个子句中仅 ~42% 严格可引用（最长逐字连续段 ≥8 字或覆盖 ≥60%），均值覆盖率 0.41。**全面逐字引用契约不可行**——mem0 输出本质是转述而非引文，强行逐字会拦掉一半有源事实。逐字校验的正确粒度是**限定词/括号级**，不是全子句级。

## 结论与置信度

**结论：来源门在部署形态（模型语义判定 + 确定性守卫 v3）下通过预冻结停止门，可在固定 23 条上作为图事实准入件使用；语义层的"隐含推断 vs 有源支持"分歧并未消失（A1 raw 行为 2/2 未变），是靠守卫兜底而非模型对齐。** 依 10/1 POC 裁决约定，准入状态为"达标但带边界"：通过的门输出附 `withdrawn_qualifiers` 与守卫日志，下游（阶段 2 图构建）须保留待核标记。

**置信度**：重放可复算（输入为已归档 raw 输出），高；守卫规则与 8 验收案的机械判定沿用 10/1 口径，中高；对更大样本、其他基准的推广不下结论。守卫为确定性规则，无随机性。

## 限制

- 守卫的限定词校验**渠道盲**：C8《教父》英文名实际有图片 query 渠道支持，守卫只能降级为待核、无法自动归因到 query 渠道；渠道感知校验是下一步。
- 括号外的无括号限定（v1 的"难受"缺"但我还好"、同行者推断）守卫修不了——这两类依赖 v2 prompt 规则的语义修复，说明**纯规则防线有上限**，模型规则与守卫是互补关系。
- 停止门 PASS 限于本固定 devset；未做新模型运行（1b 跳过），未触碰真实库/图。

## 下一步

1. 守卫 v3 作为阶段 2 图构建的事实准入件：图边/顶点带 `admission_status`（keep=有源、weaken=待核、withdraw=拒绝）与 `withdrawn_qualifiers`。
