## 论文里真正值得迁移的方法

EvoOntology 的对象是**异构数据智能体**，不是个人对话记忆。它把本体分为内容层（术语、映射、约束、证据）、模式层和工具层；智能体按需 `browse/resolve`，而不是在每次任务里静态塞入整个语义层。失败轨迹先归因到一层，再做带类型的局部编辑，最后在同模型、同任务和同预算上与父版本配对验证，通过才接受。[原文方法](https://arxiv.org/html/2609.15779)尤其要求每条语义主张能落回具体数据探查证据。

论文在 DDR-Bench 的四骨干分析子集上报告：仅工具层演化相对无本体基线 +13.2 Traj-Wise，内容层 +8.7，模式层 +3.6，完整三层 +20.0；取消配对验证门控使最终分数下降 11.2 点，取消失败归因下降 6.3 点。去掉内容对象中的映射或证据分别下降 13.4、8.7 点。[原文消融](https://arxiv.org/html/2609.15779)给的是该数据智能体任务的机制证据，**不能把这些点数当作我们中文 LoCoMo 图或 Jev 的预期收益**。论文中“ReAct + Memory”是检索旧执行轨迹，和当前 Mem0 事实记忆也不是同一种对照。

原文 v1 的摘要写“四种骨干”，主实验配置和表 1/3/4 实列**六种**，深入消融则明确只分析四种。后续引用总体表和消融表要分别注明分母，不把这处文本不一致解释成模型效果证据。

## 当前项目的来源映射缺口：可复算的实数

在 2026-09-25 中文无图归档中，**1,979** 道题的 top-15 检索记录共出现 **29,685** 次，覆盖 **1,780 个不同记忆 ID**；这 1,780 条都带 `session_id` 和 `session_date`，但 **0 条**带 `dia_id`、`turn_id` 或来源 turn ID 列表。融合图归档的 **1,980** 道题和 **1,780** 个不同向量记忆 ID 也是 **0 条**有精确 turn 来源。融合图候选覆盖 **1,476** 个不同 ID、59,378 次候选出现，归档候选对象没有元数据；其中 **735** 个不同图 ID、2,768 次入选最终上下文。数字覆盖的是**被这两份归档检索到的记录**，不是完整 Chroma 库。

把这 1,780 个向量记忆 ID 按 `user_id + session_id` 接回中文原始数据后，每条记忆所属会话含 **10–47 个 turn，中位数 21，九十分位 35**。其中 **1,691/1,780** 条记忆来自至少有一个图片 query 的会话，**1,383/1,780** 来自至少有两个 query 的会话。这里**只是在量化会话级标签的歧义**：不能据此说 1,691 条记忆受图片字段污染，更不能把一条记忆机械归到同会话任一 query。恰恰因为一个会话可有几十轮、多张图片，仅有 `session_id` 不足以支撑事实级溯源。

`EvaluationPipeline.ingest_case` 把每场会话的所有 turn 合成一次 Mem0 `add_memory`，元数据只写 `session_id`、`session_date` 等会话级字段。因此，归档记录可以追到某场会话，却不能直接判断一条摘要中的某个时间、人物或地点来自 `D27:6` 的文字、图片 caption，还是错误的 query。`conv-50_qa65` 的白山瀑布错接需要人工回读整场会话才定位；[两次提取 POC](m2_image_query_ablation_poc_zh.md)已证实仅删除那条错误 query 会把“9 月拍摄”关系接回钟楼。这是“映射到源数据＋证据记录”的本地缺口；不能因为有 `session_id` 就声称事实级可溯源。

一条 Mem0 记忆可能综合多个 turn，未来来源字段应是**来源 turn 集及每项主张的支持关系**，而不是随便附一个 `dia_id`。归档里缺字段不证明所有底层程序绝无其他来源记录，但当前答题/图/Jev 路径没有看到可用的精确映射。

## 结论、置信度、下一步优化建议

**结论：** 论文最直接支持当前复盘的做法是“有源映射的局部编辑＋同条件配对验证”。本项目目前连记忆事实到原始 turn 的映射都没有，而下游又有日期透传、展示顺序和评分可见性的问题；现在增加图类型或把更多图候选静态塞入 15 槽，无法针对已观察到的主要失败机制。论文静态语义层基线在若干模型上退化，也提示“更多语义内容”不等于“更好使用”，但这只是跨任务类比，仍需中文试验。

**置信度：** 论文方法和表格、代码输入路径、归档 1,780 条检索到的记忆无 turn ID 均为高；当前三层标签为基于已审计病例的中等置信度归因；“哪一层带来最大中文净收益”未知，不能从 EvoOntology 的 DDR-Bench 数字推断。

**下一步优化建议：**

1. 优先做**记忆主张到源 turn 的映射审计**：挑已核清的中文时间、列表和图片病例，逐项标出事实是否被源 turn 直接支持、是否混入 query/caption、是否把会话日当事件日；先保留可复核侧车表，不改生产图。
2. 先验证两个接口修复：图日期透传和 Jev 完整证据可见性。各自固定候选集、内容、槽位和模型，记录必要事实新增、旧事实被挤出、答案是否实际引用；单变量配对，控制调用上限。
3. 模式更新只接受能解决已归因失败的具体类型/关系，并在独立中文题上同时检查事实覆盖、完整答案、反伤和调用成本。当前离线 RSI 的 gold-source 上界与真实无标签学习严格分开。
