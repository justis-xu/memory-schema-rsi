# 中文 RSI 验证器：来源话轮增加后的人物归属病例

> 2026-09-27。原始输入、12 次调用及完整回复：`results/analysis/m2_zh_rsi_relation_verifier_poc_20260927.json`；复现脚本：`scripts/m2_poc_zh_rsi_relation_verifier.py`。调用的是实验 RSI 的 `verify_answer`，未调用答题器、裁判，也未运行完整 `repair_case`。

## 问题、输入与判定口径

上一阶段已堵住 `supported` 却没有有效支持 ID 的接受路径。本次追问：**有效 ID 指向的来源话轮，是否真的支持题目所问的人物关系？** 三题均来自已人工回源的中文 LoCoMo 病例：一道正例（梅尔与孩子们画画），两道错人负例（把黛博拉与她妈妈的朋友所做之事归给乔琳；把卡罗琳项链的象征意义归给梅拉妮）。负例属数据集 category 5；其 `adversarial_answer` 不能当作真实金标。这里的正负标签来自逐条原始对话审读，不输入验证器。

每题固定同一个拟议答案，比较仅给回答 turn（`answer_only`）和给连续问答两轮（`pair`）。每臂两次，顺序为 A–B–B–A，共 12 次验证器调用；模型 `glm-5.3-flash`，配置温度 0，客户端重试关闭。脚本按运行中逐次写出结果，记录原始回复、解析状态、支持 ID、token 用量、来源内容与数据集 SHA-256。两臂的格式相同，`pair` 多一条有说话人的上文，因此同时改变了证据内容和输入长度；这不是纯粹的“关系标签”干预。没有对大样本随机抽样。

| 病例与人工源关系 | 仅回答 turn，两次 | 问答两轮，两次 |
| --- | --- | --- |
| `conv-26_qa111`：梅拉妮本人说与孩子们画画，拟议答案有源 | `supported` 2/2，ID `D8:6` | `supported` 2/2，含 `D8:6` |
| `conv-48_qa233`：乔琳问的是**黛博拉和黛博拉妈妈的朋友**做了什么，拟议答案错归乔琳 | `missing` 2/2 | **错判 `supported` 2/2**，ID `D28:6`、`D28:7` |

按“错人答案出现 `supported`”这个事先定义的风险口径，两个负例各有 2/4 次误受，正例 4/4 次未被拒。但这只是固定三题、每臂两次的**定向病例**，不可写成准确率或总体误受率。`contradicted` 对项链题未必是最严格的逻辑标签：来源证明所述项链属于卡罗琳，不能排除梅拉妮另有项链；这里关键是**没有来源支持所拟的梅拉妮项链答案**，`missing` 或 `contradicted` 都不会误受。

## 具体失效机制

- `D28:6` 原文是乔琳对黛博拉说“**你和你妈妈的朋友们**做了什么”，`D28:7` 是黛博拉回答“我们一起回忆往事，翻看她的照片”。两次 `pair` 的验证器理由分别明写“**黛博拉与妈妈的朋友们**”及“她们”，却仍判关于**乔琳**的拟议答案 `supported`。这不只是没读到人物名，而是理由与最终状态不一致。其有效支持 ID 会通过上一阶段的编号门槛；若同样回复发生在修复的第二次验证，现有接受分支会接受该拟议答案。此处只证实门槛的可能失效方式，未证实完整修复链实际这样运行。
- `D4:3` 的说话者是卡罗琳，且说“这条项链对**我**特别重要”。仅给这一轮时，验证器两次只核对“象征爱、信念和力量”，忽略题目限定的“梅拉妮的”；补入 `D4:2` 梅拉妮向卡罗琳提问后，两次都辨出项链主人。可见来源 ID 真实、内容词面吻合，仍可能错配所有者。
- 正例的 `D8:6` 是梅拉妮本人“我们喜欢一起画画”，两种输入均保住 `supported`。这只是这一题的反伤检查，不能推断更广的误拒风险。

三题的原始话轮已完整嵌在结果 JSON；`D28:6/D28:7` 和 `D4:2/D4:3` 的问答关系都可独立复核。脚本把说话人显式写入来源记录，是对验证器相对有利的呈现；真实 SourceGraph 是否能召回同一组话轮、排进 15 槽、产出相同答案，均未验证。

## 对后续实验的约束

**结论：** 当前实验验证器在这两个中文错人病例中都曾输出带有效来源 ID 的错误 `supported`；增加上文在两题上的效果方向相反。来源编号门槛解决了无 ID 的提交漏洞，但未解决事实主体归属。

**置信度：** 对这 12 条实际回复、来源话轮内容与当前解析/接受代码的对应关系为高；对其他中文题的发生频率、真实 SourceGraph 输入下的行为、完整 RSI 修复接受和答案影响均未知。

**下一步优化建议：** 将人物、关系、状态与时间的闭合检查作为独立于 `support_ids` 的验收字段，并在未用过的中文样本上比较误受与正例反伤，再决定是否进入答题链。

`support_ids` 是**可定位性**字段，不是有源事实判定。下一步应在冻结的候选和来源上下文上，单独记录“问题人物—事实主体—谓词—状态/时间”是否逐项闭合，以及哪些原有直证被挤走。先选更多未用于本次观察的中文错人、多主体和直接正例，预注册问题、调用上限、正例反伤及等槽对照，再比较具体的关系约束方案；不能只因这三题就加一个“总补相邻 turn”策略或把验证器提示词改动当成答题收益。若要评估 RSI 净收益，还需独立跑答题/接受链并同时记录原答案、重答、支持来源和人工有源关系。
