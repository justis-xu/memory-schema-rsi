# 当前中文图实验：源清单读取是否完整

> 2026-09-29。沿用当前中文主轨道十个 `zhfull:locomo:*` owner，以配置的 `Mem0Backend.get_all_memories(user_id)` 对照同一 Chroma SQLite 文件的只读直接枚举。脚本 [`m2_verify_current_source_enumeration.py`](../scripts/m2_verify_current_source_enumeration.py)，[逐用户结果和前后逻辑指纹](../results/analysis/m2_current_source_enumeration_20260929.json)。零模型推理、零记忆/图写入；不读取用户以外的原文写入报告。

## 结果

`get_all_memories` 当前设置每次上限 **1,000 条**；十个 owner 单个最多 **224 条**。直接 SQLite 枚举合计 **1,800 条**，实际 Mem0 API 返回 **1,800 条**。十个 owner 均逐 ID、正文、user_id、session_id、session_date 一致，没有重复、缺项或多出 ID；前后源库的对应逻辑指纹相同。

| conv-30 | 102 | 102 | 一致 |
| conv-41 | 209 | 209 | 一致 |

| conv-43 | 211 | 211 | 一致 |
| conv-44 | 186 | 186 | 一致 |

这关闭了[图快照契约报告](m2_graph_snapshot_contract_zh.md)提出的一个**当前本地快照**缺口：对这十个 owner，现有 `get_all` 的返回不是只含前 20 条的默认结果，也没有在本次读取中触及 1,000 条上限。图实验可以基于这份完整可见清单构造源身份快照；不能把这句话推广到超过上限的 owner、其他机器、历史旧库或未来写入后的状态。

## 结论、置信度、下一步优化建议

**结论：** 当前本机十个中文 owner 的源 Memory 枚举在 ID、正文和场次元数据上与 SQLite 可见源完全一致。后续独立图实验的**源清单完整性**已有本次时间点的证据；阻止当前中文 Graph 净收益验证的主要剩余项转为关系抽取成功状态与事实来源、图版本、候选实际入槽及同条件答题，而不是这十个 owner 的 `get_all` 截断猜测。

**置信度：** 实际 API/SQLite 对账和前后逻辑指纹为高。没有并发写入锁，前后相同不能排除读取中短暂变化；Mem0 默认不返回已过期记录，本结论只覆盖当前可见源。没有证明 581 条旧结构缓存语义正确，也没有证明图服务当前持有这些 Memory 或任何关系。

**下一步优化建议：** 独立实验启动时重新取清单并保存每 owner 指纹、读取时间和上限；若任一 owner 接近 1,000 条或前后指纹变化，拒绝称 `complete`。在此基础上逐 ID 标出提取成功、合法空、失败和来源支持等级，构建独立版本图后才做候选和答题对照。不要把这次完整源枚举误写成完整中文图已就绪。
