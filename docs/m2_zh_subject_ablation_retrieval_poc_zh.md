# 中文错人题：去人名召回能补反证，也会带入干扰事实

> 2026-09-27。当前纯中文 `conv-48` Chroma 主记忆库，脚本 `scripts/m2_poc_zh_subject_ablation_retrieval.py`，逐条前 45 与重排前 15、调用记录：`results/analysis/m2_zh_subject_ablation_retrieval_20260927.json`。这是**单题定向检索病例**，没有图、答题器、裁判或 Jev 决策调用。

## 问题、样本与预设对照

历史 `qa180/qa233` 只换“黛博拉→乔琳”，四臂最终上下文几乎全换；旧日志没保存粗排向量池，无法定位目标记忆是在 embedding 首召还是 rerank 丢失。本次在**同一个当前库**固定三种问法：原问“乔琳和妈妈的老朋友们做了什么？”；去掉题目人物“妈妈的老朋友们做了什么？”；正确人物“黛博拉和妈妈的老朋友们做了什么？”仅作 oracle 上界。每句预算向量前 45、重排前 15，最多 3 次 embedding 和 3 次逻辑重排（客户端每次至多尝试两个 HTTP 端点），串行执行。反伤检查：乔琳相关事实会不会被挤走，以及去人名后是否仍混入乔琳饭局。当前库没有 `schema_rsi_atomic` 集合；这轮直接调用 Chroma 主集合和项目 `RerankClient`，不是完整 Graph/Jev/答题管线。

当前目标记忆 `53330642-…` 明写“黛布与已故母亲的老朋友重新联系、回忆往事、翻看照片”；干扰记忆 `d2e2e49f-…` 写乔琳在 2023-02-21 与普通朋友吃晚饭。它们与 2026-09-25 归档的旧 ID **不同**，不能把本轮当旧评测的严格复现。

## 实际运行与结果

首轮脚本把 Chroma 的 `documents` 传给重排器，但本 Mem0 集合的正文在 metadata 的 `data` 字段，`documents` 为 null。首个 `RerankError` 因请求内容错误而**不能判断服务可用性**；脚本停止并保留记录。随后在原上限内重新取原问和去人名问两次 embedding，保存前 45；从本地 SQLite 按已存 ID 补正文，重排这两组**冻结候选**各一次。两次有效重排均成功，实际使用 DashScope native 接口。总计 3 次 embedding、3 次逻辑重排（含第一次无效输入），未跑正确人物 oracle，未越过预设调用上限。脚本的正常运行分支已改为读取 metadata `data`，保留这次错误和恢复过程供审计。

| 问法 | 目标黛布记忆 | 乔琳饭局记忆 |
| --- | --- | --- |
| 原问，乔琳 | 向量前 45 **未见**；无法进入重排 | 向量第 **5** → 重排第 **2** |
| 去人名关系问 | 向量第 **1** → 重排第 **1** | 向量第 **33** → 重排第 **3** |

两组向量前 15 只共享 3 个 ID，重排前 15 也只共享 3 个。去人名后目标事实确实可达，但重排仍把“乔琳普通朋友饭局”带到第 3；若直接把两组记忆混作同一人的证据，会重复历史错配。去人名同时把一些乔琳记忆换成黛布的其他生活事实，不能说没有反伤。正确人物 oracle 未执行；旧归档的 `qa180` 能召回旧目标记忆只是历史参照，不是本次当前库 oracle 的测量。

运行前后 `chroma.sqlite3` 文件 SHA-256 **不同**（原始及两次后续哈希在机器结果），所以不能写“数据库字节完全未变”。本轮没有调用记忆写入接口；事后 SQLite `quick_check=ok`，`conv-48` 的 `user_id` 元数据计数仍为 224，两条跟踪记忆 ID 与正文仍在。以上只证明这几项逻辑数据可见且库可读，不证明数据库所有内容未变。Chroma 打开客户端可能改变内部元数据，但本次没有进一步定位具体字节变化。

## 结论、置信度与下一步优化建议

**结论：** 在当前中文库，这道错人题的目标反证是**向量首召不可达**，并非被重排排出前 15；去掉人名后它立即成为向量与重排第 1。人物词显著改变检索方向。去人名不是安全答题策略，因为饭局仍被重排到第 3，必须再核“问题人物—事实主体—活动”的关系。

**置信度：** 对两条当前正文、向量名次、冻结候选重排名次和调用账为高；对“人名替换导致该题候选差异”是单次同库对照，置信度中高。未运行当前正确人物 oracle、完整 Mem0 `search_memory`、Graph 或答题器；不能估计总体误受率、Jev/RSI/Graph 净收益，也不能从当前版本反推旧版 embedding 的准确位次。第一次无效请求及 SQLite 字节变化均限制“完全无副作用”陈述。

**下一步优化建议：** 把去人名关系检索视作**反证候选补充**，原问人物和源话说话者仍决定答案归属；先在预选更多中文一词换人/多主体题上，冻结主库版本，记录粗排、重排与源 turn，比较目标反证入槽以及已有直证挤出。若要测试最终答案，再独立固定 15 槽、加入关系验收和重复作答；不要只因召回第 1 就宣称修复了错误答案。
