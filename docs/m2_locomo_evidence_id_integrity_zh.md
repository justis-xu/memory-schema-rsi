# HF LoCoMo 英中证据 ID 完整性审计（2026-09-27）

## 问题与范围

水彩画题在当前无图检索的前 15 条中已有完整关系，不能继续作为当前图补缺事实的正例。本轮回到 HF LoCoMo 英中数据底座，检查 `qa[].evidence` 是否确实指向同一段对话中的 `dia_id`。逐条遍历 10 段对话、1,986 道 QA、2,815 个原始 evidence 列表项；英文 `locomo10.json` 与中文 `locomo10_zh.json` 的 evidence 数组逐题相同，轮次 ID 集合逐段相同。输入路径与 SHA256、逐题明细见 `results/analysis/m2_locomo_evidence_id_integrity_20260927.json`，复算脚本为 `scripts/m2_audit_locomo_evidence_id_integrity.py`。零模型调用，未改数据集。

## 结果

2,806 个列表项可逐字匹配真实 `dia_id`；另有 9 个列表项各影响 1 道题（9/1,986 题）。其中 6 个是可按格式定位的记录，3 个不能安全确定意图。四个“多个 ID 合在一个字符串”的列表项拆开后对应 13 个真实 ID；因此原始列表项数与展开后的证据 ID 数不能直接比较。这里计的是**指针完整性**，不是答案金标的正确率，也不是中文翻译错误率。

## 对当前代码与旧结果的含义

- `src/schema_rsi/benchmarks/locomo.py` 装载时原样保留 `evidence`。其 `evidence_in_window` 只解析 `D<场>:<轮>` 并计算场次偏移加轮号，没有核该 ID 是否真的存在。用中文文件全历史窗口实测：`conv-42_qa58` 的 `D10:19` 和 `conv-47_qa38` 的 `D4:36` 均使函数返回 `True`；`conv-50_qa69` 的 `D30:05` 也返回 `True`，虽无法逐字匹配真实 ID；含 `D` 的 `conv-42_qa88` 返回 `False`。`scripts/eval_baseline.py` 使用该函数筛选题，因此窗口准入可能与真实证据存在性不一致。
- `experiments/schema_rsi/analyze_all_locomo.py` 将原始 evidence 字符串直接拼成 `T:user|<ID>` 后与检索到的 turn ID 求交。合写项、损坏项和前导零项不会匹配正常的单个 turn ID，因而这些题的 evidence 命中代理指标可能被低估。这个影响只限于使用该代理的分析；未证明主 QA 分数因此改变。
- 格式上能定位真实轮次，仍不等于该轮语义支持答案。尤其多模态题须连同 `query`、`blip_caption` 和正文一起核，不能把正文没有片名/日落误报为完全无源。原始图像内容本轮未逐张验证；图像查询字段也不自动等于视觉真值。

## 决策与后续

暂不改英文或中文 benchmark 文件，也不把本轮格式归一结果混入旧运行。若要修，先为数据集产出版本化补丁：6 道格式题可列出机械候选；3 道待核题保留 `unresolved`，由原始来源与题意共同决定。适配器入口应校验 evidence 的实际 `dia_id` 与窗口位置，明确报错或排除无法定位的证据；旧成绩继续标注原数据版本。

本轮发现的是一项小范围数据/筛题完整性问题，不足以解释图或 Jev 整体效果。下一步回到中文源话和当前同版检索，优先找“必要事实确实未入最终 15 条、且图候选有可靠来源”的新病例，再用冻结候选和答题对照验证净增与反伤。
