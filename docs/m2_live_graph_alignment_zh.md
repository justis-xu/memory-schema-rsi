## 问题与范围

Jev 的新追踪字段已落地，但要做当前纯中文图/Jev 对照，图的 Memory 顶点必须与中文向量库的 ID、正文和用户隔离一致。配置指向本机 HugeGraph `hugegraph`；HTTP `/versions` 返回 200 只能证明服务在线。此轮固定取此前五道中文题各自重排前 3 条，共 15 个当前向量 ID，再加已核实存在于当前库的约翰签名篮球 ID，共 16 个 ID，到活图逐个只读查 `Memory.memory_id`。

## 观测

- 服务在线，图名存在；但 **0/16** 个当前中文向量 ID 能在活图找到对应 Memory 顶点。这个固定小样本不能证明全图都没有当前中文记忆，却足以阻止直接把这 16 个已知种子当作当前图路径运行。
- 从活图只读取出的一个 Memory 顶点是英文 Caroline 记忆，`user_id=locomo:locomo_conv-26_qa0`；当前中文库使用 `zhfull:locomo:conv-*`。至少这一条属于不同数据/用户隔离轨道，服务在线不能当作当前中文图已构建。
- 该进程加载的本地图键属性映射只有 `Memory: memory_id`。`GraphRetriever.retrieve_fused` 的自动跳转依赖 Entity/Event/Preference/Concept 键映射；若不先加载或创建相应 schema，这个进程即使有匹配种子也不会做这些节点跳转。此项是当前进程配置观察，不能据此断言服务端所有 schema 不存在。

## 结论、置信度与下一步

**结论：** 当前活图不具备与这批纯中文向量 ID 直接配对的可核条件。此时跑 Jev 或 Graph 对照，很可能只是测到空图/旧英文图，不能用来判断中文机制收益。**置信度：** 服务响应、16 个 ID 的查找结果、单个英文顶点及本地键映射为高；整图顶点构成、历史版本来源和可构建的中文图质量未知。

**下一步优化建议：** 若要测试当前中文图/Jev，应先在隔离 graph 名称下用当前 1,995 条中文记忆 ID 构图，保存向量逻辑指纹、图顶点/边数量、样本 ID/正文/用户匹配和 schema 键映射；在不触碰旧英文图的前提下，先验证种子→节点→候选路径。构图若需要实体提取模型，单独定样本、调用上限和反伤检查；确认图匹配后再用新 Jev 日志做小型中文对照。当前阶段不启动答题调用。
