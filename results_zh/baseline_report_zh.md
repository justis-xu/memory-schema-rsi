# locomo-zh 中文轨道全量基线报告（zhfull）

- 跑批：`results_zh/zhfull_locomo_20260925_115806.jsonl`（2026-09-25 11:58–12:22，1986 题落盘 1982）
- 精准 regrade：`results/precision_regrade_zhfull.jsonl` + `results/precision_summary_20260925_123107.json`（12:58，判分 glm-5.3 非 flash）
- 配置：mem0 提取 + 向量检索 + rerank，无图，官方 prompt 预设（英文 prompt 直填中文内容）；宽松 judge flash 档，与英文基线口径一致
- 英文对照：`results/precision_summary_20260925_023601.json` 的 A 臂（同配置基线，2026-09-25 凌晨跑批）

## 结论（先行）

1. **中文基线成立，主体指标与英文 A 臂在同一水平**：宽松 J 91.87% vs 英文 92.72%（-0.85pp，
   噪声带内）；精准 exact 64.69% vs 66.41%（-1.72pp ≈ -27 题，略超英文终审夜间漂移
   ±15-20 题的带上沿，方向为负但幅度小）。
2. **唯一明确超噪声带的差异是 adversarial 编造率**：编造 84.0%（373/444）vs 英文 78.0%
   （348/446），+6.0pp（约 +25 题等比）；干净拒答 45/444（10.1%）vs 70/446（15.7%）。这是
   最像真实语言因素的信号，但本轮非配对、非同夜，只能列为待查假设，不能定因。
3. **确定性日期规则对中文基本有效，没有发现「2023年5月7日 vs May 7, 2023」格式互译误判**：
   匹配在结构化（年，月，日）层进行，跨格式实测可对上；中文 gold 0 条英文格式。真实的 det 层
   缺陷有两个（数字与「年」之间的空格、season 自匹配恒 False），合计 4 条误判，全部被 LLM
   judge 纠正，**零分损**（final 一律取 judge）。
4. token/hedge 确定性规则在中文上如已知结论全部失效（决定性覆盖 11.4% vs 英文 64.6%），
   汇总只看 LLM judge，本报告所有精准数字均来自 glm-5.3 严格 regrade。

## adversarial 编造率：唯一超带差异

- 宽松口径就已经差 9.2pp（42.8% vs 52.0%）：flash 宽 judge 在中文上判对得更少。
- 精准口径：干净拒答 10.1% vs 15.7%（-5.6pp，约 -25 题等比）；拒答带猜测 26 vs 28（持平）；
  纯编造 84.0% vs 78.0%（+6.0pp）。
- 参照系：英文终审夜间漂移 ±15-20 题（约 ±1.0-1.3pp on 1538），adversarial 这个 ~25 题量级
  的差**超出带**，且方向一致出现在宽松与精准两层。
- 待查假设（本轮无法定因，均未验证）：(a) 官方英文 prompt 预设下中文作答更"热心"、更少生硬
  拒答；(b) 中文提取保留更多似是而非的细节 → 检索回灌 → 有材料就答；(c) judge 对中文"部分
  拒绝"（拒了主体但顺手补了猜测）分级更严。下一轮应做同夜中文配对消融（换中文化 prompt /
  收紧提取）再下结论。

## 专项核查：确定性日期规则对中文是否失效

审计全部 254 条 `rule=date` 记录（temporal 共 321 题：date 决定性 156、duration 17、其余
交给 LLM），**未发现中文日期格式被系统性误判**：

- **通过率**：date 有判定 156 条中通过 133（85.3%）；其中宽松判对的 147 条里 det 通过 133
  （90.5%）。失败 23 条定性分类：真日期不符（含"约/下旬"粒度差）10 条、宽松已判错 8 条
  （final=wrong 不变）、**season 自匹配缺陷 3 条**、**空格日期缺陷 1 条**、边界 1 条。
- **跨格式安全**：gold 'May 7, 2023' 与 pred '2023年5月7日' 在 day 粒度结构化匹配实测为
  True（`src/schema_rsi/evaluation/precision.py:92-105` 按 (y,m,d) 比较，不比字面）；中文
  regrade 的 gold 含英文月份 0 条，22 条 pred 混有英文日期也可正常解析。中文数字（六月、
  十七日）与阿拉伯数字均支持（`precision.py:143-161`）。
- **缺陷 1（中文特有）**：数字与「年」之间不允许空格——正则在年份与"年"字连接处缺 `\s*`
  （`precision.py:146,151,156,160`），"2022 年 12 月 21 日"只能解析出年。temporal pred 中
  该空格模式共 5 条：1 条成为决定性误判（conv-41_qa1，det 判 fail、judge 判 exact、
  final=exact），3 条被推迟交 LLM（安全），1 条走时长规则不受影响。**影响面：1 条误判，
  0 分损。**
- **缺陷 2（中英同病，非语言因素）**：season 粒度 gold 永远匹配不上 pred 的 season 引用
  ——`DateRef.matches` 对 season 要求 `other.m` 非 None（`precision.py:97-99`），而 season
  引用从不带月份。中文 3 条 identical 字符串误判（conv-48_qa27、conv-48_qa31、conv-49_qa73，
  gold='2022年夏天' pred 含'2022年夏天'仍判 fail，全部被 judge 纠为 exact）；**英文 A 臂同样
  中招 ≥5 条**（conv-41_qa59、conv-43_qa63、conv-48_qa27/31、conv-49_qa73 的英文版，
  'Summer 2022' vs 'summer of 2022' 判 fail）。影响面：中文 3 条误判，0 分损；修法是 season
  引用携带代表月份或 matches 增加 season-vs-season 同季节判断。
- **连带效应**：这两个缺陷把 det_vs_judge 一致率压到 0.7129（n=209；英文 0.7518，n=1281），
  约一半差距来自缺陷与子集构成不同。det 决定性覆盖中文仅 227/1982=11.4%（英文 64.6%），
  因为 token 规则对中文输出 0 个实词（`content_tokens` 只匹配 `[a-z0-9]+`，`precision.py:228`）
  全部交 LLM——与台账已知结论一致，非缺陷而是设计上的失效。

## 真实样例（原文照录）

**样例一（好：temporal，中文日期 exact，det 与 judge 双过）** — conv-26_qa0
> Q：卡罗琳是什么时候去LGBTQ互助小组的？　gold：2023年5月7日
> pred：卡罗琳于2023年5月7日参加了LGBTQ互助小组，听到了鼓舞人心的跨性别者故事，感到开心和感激。
> det：gold='2023年5月7日'(day) vs pred 日期 ['2023年', '2023年5月', '2023年5月7日'] → 通过；
> judge：exact（日期精确匹配，无对冲）。

**样例二（好：adversarial，干净拒答，中文里 10.1% 才做得到的事）** — conv-26_qa158
> Q：梅拉妮的奶奶来自哪个国家？
> pred：记忆中没有关于梅拉妮奶奶来自哪个国家的信息。
> judge：exact=干净拒答（明确说无信息，未编造）。

**样例三（坏：adversarial，宽松判对、精准判编造——84% 编造率的典型长相）** — conv-26_qa156
> Q：在收养过程中，梅拉妮对什么感到兴奋？（gold 为空：对话中无此信息）
> pred：梅拉妮对像她那位朋友一样，通过收养成为母亲、为需要关爱的孩子提供一个安全有爱的家感到兴奋。朋友的收养经历（过程虽漫长但全家幸福）启发她觉得自己也许也应该考虑收养，并向卡罗琳询问了入门建议。
> judge：wrong=编造（答案把"朋友的经历+她本人的设想"当成对她感受的事实回答）。
> 这 119 条"宽松对/精准编造"是两臂共同的最大失分池（英文 134 条）。编造总量中文 373 vs
> 英文 348（+25），拆开看：宽松层判错（本就直接 wrong）中文 254 vs 英文 214，宽松判对但
> 精准定编造反而中文 119 vs 英文 134——两层各有移动，总差 +25 超噪声带。

## 告诫清单

1. **不要拿宽松 91.87% 当成绩讲**：宽松虚高 ~25pp 是两轨共识，一律引用精准 exact 64.69%
   （宽松判对里 25.6% 只是 partial）。
2. **adversarial 编造率 84% 是本基线最大短板**，且与英文的差距（+6pp）超出噪声带——但在
   做同夜中文配对消融（prompt 中文化 / 提取收紧）之前，不要把它归因给"中文能力"或"prompt
   语言"中的任何一方。
3. **跨轨对比的噪声参照**：英文终审的夜间漂移 ±15-20 题；本次中英对照**既非同夜也非配对**
   （英文凌晨跑、中文午间跑，题目集还差 4+1 题），单口径 ±1.3pp 内的差异都不要讲成结论。
4. **确定性层在中文只可信日期/时长两条规则**，token 与 hedge 全失效（hedge 计数 0/1982 是
   英文词表使然，不是中文不 hedge）；det 结论只能当 LLM judge 的旁证。
5. det 层两个已量化缺陷（空格日期 ×1、season 自匹配 ×3，中英同病）零分损，但复用
   `strict_check` 做快速判分前要先修，否则 det_vs_judge 会继续低估。
6. **覆盖缺口**：1986 题落盘 1982，缺 conv-42_qa255（adv）、conv-43_qa113（temporal）、
   conv-44_qa115（temporal）、conv-47_qa188（adv）——loader 产出齐全（实测 1986），是跑批
   中途丢弃（限流重试耗尽即弃，`scripts/eval_full.py:118-132`）；英文 A 臂同样缺 1 题
   （conv-41_qa34）。下次跑批后应做缺口对账再出数。
7. 官方英文 prompt 预设直填中文是本轮刻意保持的口径；任何 prompt 中文化改动都要另开对照轮，
   不可与本基线混比（台账既定规则）。
