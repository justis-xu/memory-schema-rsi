## 0. 结论先行

1. **检测端：decider 的优势迁移到中文，且证据形态比英文更干净；laya 不可用，方向甚至是反的。** decider missing AUC = 0.9821（机器值，我重算逐位一致，`conv42_zh_poc.json:1123`）：全场唯一无漏提取的 session_16 被 decider 打出并列最低分（0.0634），28 个正例中 27 个高于它。laya AUC = 0.2857（`:1084`）——不仅低于 0.5，它把唯一干净 session 打到 0.5302，**高于 28 个正例中的 20 个**（正例均分 0.3932 < 负例均分 0.5302）。门控选 decider，不讨论。
2. **但 AUC 的数值不可外推，必须直说：负例只有 1 个（28:1）。** 本次不是"正例过少"（正例 28 个），而是负例极度稀疏——AUC 完全由 session_16 这一个点的排位决定，0.9821 = 27.5/28。换一个负例结论可能完全不同。可信的表述是上面那句排序事实，不是 AUC 数字本身。
3. **基础率畸高让"升级全中"几乎无信息量。** 28/29（96.6%）session 审计确认有漏，随机升级 3 个也有 **89.7%**（C(28,3)/C(29,3)）概率"全真漏"（我算）。真正有信息量的是分布形状：decider 头部 3 名（session_24=0.524 / session_5=0.476 / session_29=0.349）与第 4 名（session_26=0.277）之间有干净断档，且唯一负例垫底。
4. **阈值建议：decider missing P(B) ≥ 0.3。** 升级 3/29（session_24 / session_5 / session_29），审计确认 3 个全有漏提取（机器值，我重放一致）；0.3 恰落在 0.277–0.349 断档中间，与英文工作点（同为 0.3、同为 3/29 升级）**完全一致**。代价照直说：漏检 25/28（89%）——这是拦最响警报的兜底门，不是主力质检。laya 同阈值升级 19/29（66%）且把唯一干净 session 卷进来，无可用工作点。
5. **payoff（中文闭环）：103 条审计漏点，nf53（glm-5.3 非 flash 重灌对照库，207 条）覆盖 16 条 = 15.5%**（机器值，我按明细重数一致）。落在英文两口径（POC 33% / 台账 12%）形成的 12%–33% 区间的低端，**方向一致：二审只能救回少数派**。升级的 3 个 session 共 11 条漏点，nf53 只覆盖 2 条（18.2%，我算）——链路的实际救回量很小。
6. **链路判定（核心问题的回答）：值得以『低成本兜底门』形态接入，用 decider、阈值 0.3；但不值得当主力质检，英文"先修提取收录范围"的结论在中文同样成立。** 与英文"现在不接入"相比松一档，理由有二：中文真值方法修掉了英文最大的标签扇出问题（我抽查 7/7 漏点关键短语确实在 session 自己原文出现），decider 的排序行为在唯一可分辨的点上是对的；但收益端 15.5% + 升级面漏点仅 2/11 可救回，决定了这条链路的期望收益上限低。

## 5. payoff（中文闭环）：升级 glm-5.3 二审能救回多少

- 机器记录（我重数一致）：103 条审计漏点，nf53 对照库（glm-5.3 非 flash 重灌，207 条，我从 chroma 直查确认规模）覆盖 **16 条 = 15.5%**。
- 覆盖样貌（我按明细归纳）：nf53 救回的多是**硬实体/具体物件**类——"蜘蛛侠胸针""毛绒小狗""写作展会""调暗的灯""YouTube 截图""不会放弃写作"等；救不回的多是**评价/情感/陪伴类**表述——"意义重大""很乐意帮忙""等不及要试试"这类 mem0 官方 prompt 收录范围外的内容，与英文台账定位的根因（`docs/search_ledger.md` 口径：收录范围而非模型档位）吻合。
- **升级面上救回更少（我算）**：decider@0.3 升级的 3 个 session 共 11 条漏点，nf53 只覆盖 2 条（18.2%）——session_24 的"毛绒小狗"与"完美的机会"，session_5 与 session_29 各自 3、4 条漏点 **0 条**可救回。即使门控全对，这 3 次二审的期望补回也只有 2 条记忆。
- 与英文口径对比：15.5% 落在 12%–33% 区间内（低端），方向一致——**『升级 glm-5.3 二审』在中文同样只能救回少数派漏点**。

## 6. 真实样例（2 个）

### 样例 1｜session_24：decider 全场最高分，审计真漏坐实，升级名单里唯一二审能救回的 session

- 审计 4 条漏点，关键短语与原文（我在 `locomo10_zh.json` session_24 原文里核过，均出现）：
  - **「毛绒小狗」** → D24:4 乔安娜："我还留着你送我的那只**毛绒小狗**呢！我给它取名叫蒂莉，我写作时它总陪在我身边。"（当前记忆把送礼方向写反了；nf53 已救回 ✅）
  - **「乌龟慢慢爬来爬去」** → D24:9 内特："我说不清为什么看着我那些**乌龟慢慢爬来爬去**会让我这么开心。"（nf53 未救回 ❌）
  - **「完美的机会」** → D24:13 内特："坚持下去，你会遇到**完美的机会**的。"（nf53 已救回 ✅）
  - **「每当有伤心事发生」** → D24:15 内特："我真的很敬佩你，**每当有伤心事发生**你都能重新振作！"（nf53 未救回 ❌）

### 样例 2｜session_16：唯一干净 session，双服务对它的处理是全报告最有分辨力的一对数字

- 三问：decider **missing 0.0634**（与正例 session_8 并列全场最低）/ unsupported 0.0793 / conflict 0.0230；laya **missing 0.5302**（高于 28 个正例中的 20 个）/ unsupported 0.6379 / conflict 0.3666（`:571-594`）。

## 7. 告诫清单

1. **负例=1，AUC 不可外推（本次最大告诫）。** 28 正 / 1 负，decider 0.9821 与 laya 0.2857 都由 session_16 一个点的排位决定；任何新负例都可能大幅改写 AUC。本报告的可信结论是排序事实与断档位置，不是 AUC 数值。
2. **基础率 96.6% 之下，"3/3 全真漏"证明力很弱**（随机 3 抽全中概率 89.7%，我算）。同理，阈值表里所有"其中有真漏数"都只差 session_16 一票，别把精度数字读成检测力。
3. **审计真值本身是模型判断。** 103 条漏点由 glm-5.3 非 flash 产出，我只验证了"关键短语在 session 原文共现"规则（7/7 抽查成立），未验证漏点清单的完备性与每条的正当性——"内特表示很乐意帮忙"这类条目是否该算必须收录的记忆，存疑（审计自己的噪声）。
4. **单一对话、单一语言、单一题材。** conv-42 是 Nate/Joanna 双人闲聊的中文翻译，无跨对话/跨题材证据；中文提取重跑过，漏点位置与英文不同构，两边数字只能比方向、不能比大小。
5. **服务条件不可控。** 两服务均走公网端点（`endpoints_used.mode = "public"`，`conv42_zh_poc.json:10-18`），温度未知；decider 分数量化/重复明显（0.0987×5、0.1123×4），阈值不应卡在重复值上。
6. **payoff 的覆盖判定是关键词匹配口径。** "covered" 指漏点关键短语能在 nf53 库中匹配，改写幅度大的等价记忆会被算成未覆盖——15.5% 是保守下界口径，但方向不受影响。
7. **升级面的二审收益更低。** 升级 3 session 的 11 条漏点仅 2 条（18.2%）可救回，session_5/session_29 各自 0 条——门控即便全对，当前升级名单上的期望补回量也只有 2 条记忆。
8. **底稿截断。** 打点摘要停在 `[20/29]`（session_20 laya 行被截），session_20 laya 及之后的底稿行未逐行对照（JSON 内部一致性已由 AUC/阈值表整体重算覆盖）。
9. **unsupported / conflict 无人工真值。** 本报告只描述这两个维度的分布，未下检测力结论；`auc_by_question` 不是它们的检测力。
